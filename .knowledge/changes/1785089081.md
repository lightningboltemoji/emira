# Outer gaps, and the second viewport they force

> Change `1785089081` — 2026-07-26

## Goal

Add a margin at the edges of the working area — `outer-gap` plus four `outer-gap-<side>` overrides —
completing the family `column-gap` and `window-gap` belong to.

## Implementation

Folding the gaps into `config.struts` at `Engine.metrics()` is one line and wrong. The arithmetic is
identical (both are `Rect.inset(by:)`) but the two insets differ over what may cross them:

- A **strut** is forbidden ground. No managed window is ever inside it, tiled or parked, which is what
  licensed insetting the cover past the menu bar.
- An **outer gap** is empty at rest and crossed in motion. The cover clips
  (`Overlay.masksToBounds`), so a strut-shaped outer gap cuts every layer at the margin's inner edge
  and a window pops into being there instead of sliding through.

So `workingArea` split. `LayoutMetrics.contentArea` is the logical viewport: where the strip lives,
what width proportions resolve against, where column 0 starts, and what every scroll target frames
against. `workingArea` keeps meaning the physical extent: tile-vs-park, capture scope, and the edge a
sliver hugs.

Picking the wrong one changes behaviour, not appearance. `Layout.visibleWindowIds` is the reducer's
`setFrame`-vs-`park` switch, so asking it of the logical viewport parks any column whose leading edge
sits in the margin, enforcing the margin by teleporting windows out of it. It also pops the
cross-fade, since the presentation plane draws that column from `naturalFrames`, which never parks.
The conversion needs no new geometry: the physical viewport in strip space is the logical one outset
by the horizontal gaps. Both queries go through `LayoutMetrics.physicalViewport` rather than each
shifting for itself, since a scope narrower than the park set is a window on screen with no layer.

## Observations

- After a reveal leaves a column flush with the content's right edge, its neighbour starts one
  `column-gap` further on while the display ends one `outer-gap-right` further on, so a neighbour
  bleeds into the margin at rest iff `outer-gap > column-gap`. Bleed is a supported state; the
  inequality is pinned as a parameterized test.
- Per-side overrides are spelled flat (`outer-gap-left`). The dotted form parses, since the grammar
  flattens a document to dotted paths in one dictionary, but it makes one key both a scalar and a
  table, which real TOML forbids — so every config using it breaks when the hand-rolled grammar is
  replaced. A test pins that the dotted form is refused as an unknown key.
- `EmiraShell` is unchanged. Outer gaps are entirely a core concern.
