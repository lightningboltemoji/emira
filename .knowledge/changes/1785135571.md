# Implement or remove the five inert verbs

> Change `1785135571` — 2026-07-26

## Goal

An audit of `Command` against `reduceCommand` found five verbs that parsed, rode the socket, were
answered `ok`, and did nothing: `move-to-monitor`, `reload-config`, `close-window`, `float` and
`cycle-height`. `CommandSyntaxTests` and `EnvelopeTests` cover every case at the syntax and wire level,
so the suite was green throughout. `Command.usage` is `emira --help`, so a listed verb is a promise.

## Implementation

Removed:

- **`move-to-monitor`** — no second strip exists to target; `State.metrics()` resolves against
  `monitors.first`. Per-monitor strips will define it.
- **`reload-config`** — the file is watched, so every save reloads. Removing it took
  `Effect.reloadConfig`, the executor's `.config` plane and the `ConfigSource` protocol, which existed
  only to give that effect a landing point. `ConfigLoader.reload()` is now internal with one caller.

Implemented:

- **`close-window`** is an `Effect` and is deliberately unacked. `AXWindow.close()` presses the
  window's own `AXCloseButton`, the public equivalent of clicking the red dot, so the app runs its own
  close path and an unsaved document still gets its sheet. The reducer changes no state: removing the
  window optimistically would assert a fact only the app owns and be wrong whenever an app declines.
  The strip closes ranks on `windowDestroyed`, the path a user-clicked close already takes. Reading
  `AXCloseButton` is a window-level attribute, not the child-tree walk `PRINCIPLES.md` §5 forbids.
- **`float`** writes a tri-state override (`nil` = follow the role). Tri-state because `float off` must
  tile a window macOS classed as a dialog; with a flag half the verb is unreachable and a
  mis-classified window is stuck. Stored even when it agrees with the role, because a subrole describes
  presentation and changes under us. It owns no geometry: floating is `departFromStrip` minus the
  refocus, tiling is `arriveOnStrip` minus the `.focus`.
- **`cycle-height`** needs no fourth animated quantity. A height change moves and resizes the windows
  of one column and nothing else, which is the per-window displacement structural edits already
  animate; `Rect.delta` carries size as well as origin, so a window that only got shorter is a
  displacement with a zero origin term. The selection is keyed by window on `Workspaces` rather than on
  `ColumnLayout`: a parallel array beside `windowIds` must survive four structural primitives plus
  reconcile and desyncs silently, and holding it for the whole set means a workspace move carries it
  without `move` doing anything. It reaches geometry through `LayoutMetrics`, for the reason
  `corrections` does — it must reach every query or they disagree about a window's height. Auto is a
  rung of the ladder (auto → ⅓ → ½ → ⅔ → auto), so one verb reaches every selection and returns.

The height correction shipped with it. `SizeCorrection.heightFloor` answered only when a window came
back **taller** than asked, so an app that refuses to grow had its answer stored and never read. Two
consequences: every return to the viewport re-issued a set the app refused and stretched a 200 pt still
into an 800 pt slot, and stacked, such a window held half a column it could not fill. The bound is now
signed (`HeightBound.atLeast` / `.atMost`, mutually exclusive by construction) and `Column`'s water-fill
pins in both directions.

## Observations

- Nothing enforces that a `Command` case is reachable in the reducer. The audit was manual and would
  have to be repeated.
- A column whose every window has a ceiling under-fills its box. There is nowhere to return the height,
  unlike the strip, which packs the next column against a narrow one.
- A height learned mid-transition rides the third animated quantity rather than the second, because
  re-running the water-fill produces two divisions of one box with no number to interpolate
  (`Motion.displaceWindow`, y and height only).
- `cycle-height` is unit-tested and has not been run on a real desktop.
