# Animate departure and arrival

> Change `1785051407` — 2026-07-26

## Goal

Closing a window moved every survivor instantly. Opening one appended a column at the far end of the
strip, so the only motion was the viewport chasing it. Both should use the signature transition.

## Implementation

A departure is a structural edit: `Layout` before and after are two different structures, so no number
the new frames derive from exists, and what animates is each survivor's displacement from where it now
belongs, decaying to zero. That is what `move-window` and `consume-or-expel` already do, so
`windowDestroyed` and `windowMinimized` route through `finishStructuralEdit`. The only difference is
that a departure has no **mover** — the window that would be drawn on top has left — so that parameter
became optional.

An arrival has the opposite asymmetry: a newcomer has no frame in the old geometry.
`StructuralSnapshot.including` seeds one — the frame its app opened it at, which is also the frame the
cover captures. That single seed gives three properties: the displacement is "from where the app put me
to where the strip wants me", so the window travels rather than appearing; the first animated frame
equals the capture-time frame, so the raise does not pop; and every column it displaces is handled by
the existing loop from the same two `naturalFrames` calls.

Animating both exposed two placeholders that a snap had hidden:

- **Focus after a departure** went to the first window in layout order, which re-framed the strip on
  column 1. Under a snap the re-frame was the whole observable event; animated, it is a full-strip
  scroll on every close. It now takes the neighbour: a surviving stackmate, else the column that slid
  into the departed one's place (right, or left when it was last).
- **`reconcile` appended newcomers** at the far end, so a new window displaced nothing.
  `reconcile(stripWindowIds:insertingAfter:)` takes an anchor. The anchor is `World.lastStripFocus`,
  not `World.focusedWindow`: an app focuses its new window before emira has adopted it, so the observer
  resolves that element to no id and `focusChanged(nil)` lands before `windowCreated`. Anchoring on
  live focus passes a unit test and appends in the product every time; the regression test had to be
  written from the observed event order.

The viewport clamp is included because the symptom is indistinguishable from the above: closing the
rightmost columns leaves the offset past the end of a strip that now fits on screen.
`Strip.offsetToReveal` clamps its answer rather than its input, since the stranding rides the "already
fully visible, don't move" branch which returns the input unchanged; `emitPlacements` re-clamps the
resting offset, which covers a strip that shrank with nothing asking to reveal anything.

## Observations

- The clamp does not apply to `center-focused-column`. Centering at the strip's ends means showing
  space past the last column, so clamping there would convert an explicit request into flush-left.
- Rubber-banding is not built. The resting invariant is.
- ~25 tests were asserting against a half-raised cover, since building a world out of `windowCreated`s
  now opens a transition. One helper — answer every capture, land every set, tick until settled — fixes
  them; tests that want instant placement now set `smoothTransitions: false`.
- Measured: closing one column of six is 41 frames / 341 ms / 120 fps behind a 79 ms capture head. The
  boot scan's six adoptions coalesce into one session.
