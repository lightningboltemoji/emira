# Window rules

> Change `1785138556` — 2026-07-27

## Goal

Let a config assign an arriving window to a workspace. `[[window-rules]]` matches on any AND'd
combination of `app-id`, `app-id-regex`, `title` and `title-regex`.

## Implementation

**A rule is consulted once, at first sight, and never again.** That makes an assignment a starting
position rather than a constraint — a window sent to `3` can be moved anywhere afterwards — and it
avoids a second authority over a window's workspace, which is derived from the strip holding it
(`Workspaces`). `windowDeminimized` is an arrival on the strip and deliberately does not consult rules:
restoring from the Dock acts on a window that already exists, so it lands where the user is.

**Boot places silently; a live arrival moves focus with the window.** The launch scan sorts a desktop
nobody asked it to sort, so walking the user through six addresses before their first keystroke is the
case rules exist to prevent. A window opened now was opened by the user, and following it is what
`revealAcrossWorkspaces` already does for a Dock click on an app living elsewhere. `wasAlreadyOpen`,
added for width seeding, distinguishes them.

**Matching rules merge top to bottom, later winning per field.** Precedence is positional, so a broad
rule can set a default a narrower one refines without the two agreeing about anything else. Written as
a merge (`RuleOutcome`) from the start, so a second and third action is one field each.

The reducer needed no new mechanism. An assigned arrival is not `arriveOnStrip`: the window never joins
the strip in view, so no columns open around it and nothing on screen moves. It is the move
`move-to-workspace` performs, from a column the window holds for one statement. Focus is set inside
`switchWorkspace`, never before it, since the switch reads current focus to record what the outgoing
workspace returns to and a window on another strip reads as nothing.

Two grammar additions. **Arrays of tables**, which `TOML.swift` previously refused by name — the subset
is "what the config is written in", and the config now needs a list. **Literal strings**, because a
rule matches on regular expressions: in a `"…"` string every backslash doubles, and `"\d"` is not an
escape this grammar admits, so it is a syntax error rather than a character class. Patterns compile at
parse time and are stored as source text, since `Config` is `Equatable` and `Codable` and a compiled
`Regex` is neither.

## Observations

- Titles are matched as they read at first sight. Many apps, Electron ones especially, create a window
  and set its title afterwards, so a title matcher can see `""` or a generic app name. `app-id` has no
  such weakness. Re-running rules on title changes would contradict the once-only rule.
- A rule can only set a workspace. `float` and an initial `width` are the next actions and the merge is
  already shaped for them.
