# A refusal is an answer in both directions

> Change `1785094427` — 2026-07-26

## Goal

Reported after `fullscreen` landed. `grow` or `fullscreen` on System Settings, which is 723 pt wide and
will not resize: the animation expands, the window does not, and the column keeps a width no window in
it can fill. The state is permanent, because the intent is stored, and the extra width is scrolled
through like content.

## Implementation

`SizeCorrection` already recorded both directions; its consultation did not.
`SizeCorrection.widthFloor` answered only when the window came back wider than asked, on the grounds
that an over-filled column overlaps its neighbour while an under-filled one is a cosmetic gap.

An under-filled column is not cosmetic. A column's width is **strip extent**: it sets where every
column to its right begins, what `offsetToReveal` scrolls to, what `visibleWindowIds` tiles versus
parks, and what the sweep captures. Quiescence for the downward direction had been left to
`Engine.isAlreadyPlaced`, which can only skip a placement when the position also matches — and a scroll
changes every position, so the diff re-emitted the refused width once per scroll.

`widthFloor` becomes `width(forQuestion:)`, an answer in either direction, and `Layout.resolvedWidth`
takes the widest width the column's windows can achieve for the width they were asked: a window that
has answered contributes its answer, one that has not contributes the intent. `max` covers both
directions in one expression, chosen by the invariant — a window refusing to shrink needs the room,
since less would overlap its neighbour, while a column none of whose windows can grow holds room
nothing can use. A mixed stack keeps the intent.

Routing the refusal into `resolvedWidth` rather than into the write is why no feedback mechanism was
needed. The resolved width is already animated, so `handlePlacementCorrected`'s existing retarget
springs the column out toward the intent and back when the answer lands, with neighbours following by
derivation. Quiescence follows: the target becomes the width the window already has, so
`isAlreadyPlaced` matches and the diff stops emitting.

Rejected: capping the window's box inside an unchanged column at the placement layer. It fixed the
re-asking and produced a reported one-frame flash, because a clamp outside the animated quantity jumps
~340 pt between two frames where a spring moves ~29. Pinned as a continuity assertion, since a settle
assertion cannot distinguish the two.

## Observations

- Narrowing can recurse: the column follows the answer down, so the next request is the answer rather
  than the question, and an app that always returns slightly less than asked walks the column toward
  nothing. A narrower answer is therefore learned only when the request that produced it was the
  question — at most one narrowing per question. Widening learns unconditionally, since too wide
  overlaps a neighbour and must be absorbed however late it arrives.
- Residual: an app that never converges costs one extra set per real event, not a busy loop.
- The height axis is still one-directional. No app on this desktop has refused a height, so the
  equivalent defect there is unobserved.
