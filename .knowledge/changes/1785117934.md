# Teardown: place the desktop on quit

> Change `1785117934` — 2026-07-26

## Goal

Stopping emira left every parked window at its ~1 pt nub. Nothing else on the machine identifies a nub
as a window, so a user who quit had to drag them back individually. Place the desktop on exit instead.

## Implementation

Every managed window on every workspace is stacked in the centre ¾ of the working area, staggered 30 pt
down-and-right, resized so their bottom-right corners coincide (`Layout/Cascade.swift`). Aligned corners
make the stagger an even band of title bar on every buried window.

It is a layout, so it lives in the core, which follows the rule a park slot already establishes: a
placement is core-owned target geometry. `State.cascadeEffects()` emits only `setFrame`/`raise`/`focus`,
so the existing `AXExecutor` runs it and the existing `axLanded`/`axFailed` answer it. No new `Effect`,
`Event` or `Command` — a quit is not a verb, and adding one would put a second door on a lifecycle that
already has three (Ctrl-C, `kill`, the menu item) reaching one function. No cover either: the cascade is
the last thing that runs, so there is nothing left to animate it and a capture round trip would only
delay the exit.

Bottom-right alignment introduced two problems:

- **Z-order.** Window *i+1* is strictly inside window *i*, so an earlier window drawn on top hides a
  later one. Every other placement relies on strip windows never overlapping. Fix: raise in cascade
  order with the focused window **last**, which also makes the trailing `focus` a no-op that brings its
  app forward.
- **Stagger overflow.** A deep enough stack drives the last windows through zero size, so the step
  compresses uniformly to keep `Cascade.minimumSize` rather than clipping the list, wrapping it, or
  letting a window collapse. Every input is total, including a screen with no room for a cascade.

The exit ordering matters because our own writes are observations: a live watcher answers each
`AXWindowMoved` with `windowFrameChanged`, the reducer re-places the window on the strip being
dismantled, and the cascade and the layout contend until the deadline. The daemon therefore calls
`WorldWatcher.stop()` first — a latch on delivery, not an unregistration of live `AXObserver`s, since
tearing those down at exit gains nothing over the process exiting and can crash on the way out.
`Teardown` holds the exit until every window lands, bounded at 1.5 s.

## Observations

- Cross-app stacking is best-effort: `AXRaise` orders a window within its own app, and re-levelling
  against another app's window requires SkyLight.
- Min/max sizes are not negotiated. An app that refuses to shrink keeps the top-left corner it was given
  and overhangs. This falls out of `AXWindow.place` writing size then position.
- A hung app delays a quit by up to 1.5 s and cannot prevent one.
