# The product, M0 through M5

> Change `1785043649` — 2026-07-25

## Goal

Build the pure reducer, the truth plane, the signature scroll and the ergonomics. One commit, because
it was built as an unbroken run of milestone slices.

## Implementation

Architecture per `IMPLEMENTATION.md` §1: `EmiraCore` imports no framework and owns animation time, the
shell blits what the core emits and feeds every failure back as an event, and the pump is never
re-entrant. Non-re-entrancy is required rather than stylistic: `orderFront` fires delegate
notifications synchronously and an AX call can complete on the calling thread, so any handler
producing an event must enqueue it. It is also what allows `dumpState` to be answered off
`Runtime.state` between pumps instead of through the reducer.

| Milestone | Contents |
| --- | --- |
| M1 | Geometry, layout engine, four structural editing primitives, reducer; interrupt/retarget scenarios pass headless |
| M2 | `EmiraProtocol` over a Unix socket (one request, one reply, close; versioned by probe, not decode), `CADisplayLink` frame clock, overlay |
| M3 | Truth plane, reads before writes |
| M4 | Cover: ScreenCaptureKit stills over a base captured excluding them, growing on retarget |
| M5 | Config file, keyboard, structural commands |

M3 splits reads before writes for two reasons: a bad scan prints a wrong report while a bad write
rearranges a desktop, and identity must be correct before anything is written, since a `setFrame` aimed
at a mis-bound window is worse than none.

Three corrections forced by a real desktop:

- The first enumerator run bound **0 of 2 windows**. `kAXWindowsAttribute` contains non-windows (Finder
  answers with the desktop, an `AXScrollArea`), and owner + frame is not a unique key (Safari carried
  two layer-0 entries with identical bounds). `kCGWindowIsOnscreen` is now consulted on a tie.
- The identity join runs against `CGWindowListCopyWindowInfo`, not ScreenCaptureKit. Its numbers, pids
  and bounds are unprivileged, so identity costs one TCC grant instead of two. `SCWindow.windowID` is
  the same integer, so capture inherits the bindings.
- Transition scope was fixed at open, so a chained scroll slid an uncaptured window in with no layer,
  showing the base through the gap. Scope now widens on retarget and never shrinks.

Two values were derived rather than chosen:

- **Scroll spring.** Solving critically-damped settle time for the target duration moved a measured
  605 ms to 336 ms; predicted and measured agreed to 3 ms.
- **Structural edits animate displacement, not position.** `Layout` mutates at once and stays the
  authority on where a window belongs; the spring carries how far behind that answer each layer is,
  decaying to zero. The exception is z-order: two columns trading places overlap at the midpoint, and
  which draws on top is a property of the command rather than the strip. `Effect.elevateLayer` is the
  only new mechanism in the slice.

## Observations

- M5 is incomplete: no menu bar and no `.app` bundle, so diagnostics go to stderr.
- Nothing restores window positions on quit. Off-screen parking is one-way.
- The viewport does not clamp to the strip's extent; closing the rightmost columns strands the offset
  past the end.
- `cycle-height`, `float`, `close-window`, `move-to-monitor` and `reload-config` parse and do nothing.
- Workspaces and window rules (M6) are untouched.
- Measurements: one-column scroll 73 frames / 605 ms / 121 fps behind a ~110 ms capture head before the
  spring retune, 41 frames / 336 ms after. RSS ~41 MB across 14 transitions; 0.0% CPU at rest. Window
  geometry verified against `CGWindowListCopyWindowInfo` in a separate process.
