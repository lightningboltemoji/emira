# the config file's format becomes a target

> Change `1785389740` — 2026-07-29

## Goal

emira is configured by hand-writing TOML, which is a fine interface for the person who built it and a
closed door for everyone else. Opening that door means a settings window, and a settings window means
deciding — before any of it is written — what it is allowed to see. A GUI that can reach the `Engine`
will eventually reach it, and then the reducer has a second caller with opinions about frames.

So this change draws the boundary and nothing else. It moves the config file's *format* — the TOML
grammar and the schema — out of `EmiraCore` into a new `EmiraConfig`, and stops. No behaviour differs
by a character: the same text parses to the same `Config`, and every diagnostic says what it said.

## Implementation

A target rather than a folder, because a folder is a suggestion. `EmiraCore/Config/` would have been
the same code in the same places and would not have stopped a settings window from importing the
`Engine`; the package boundary is the only thing that makes "it sees the config and nothing else"
enforced instead of intended. It cuts the other way too — `emira config` can reach the file format
without reaching the shell, which is what the CLI could not do before.

The split is along a seam the naming already claimed: `Command`/`CommandSyntax`, `Config`/`ConfigSyntax`.
The **values** stay in `EmiraCore` because the reducer reads them, along with `Command`, `KeyChord` and
`WorkspaceName`, which the CLI needs and the schema merely validates against. What moved is `TOML.swift`
and `ConfigSyntax.swift`, together — `TOMLTable` and `TOMLValue` are internal, and moving them as a pair
means the schema still reads them as same-module neighbours and nothing had to be made public to survive
the trip. The two files gained one line between them, `import EmiraCore`, and the 872 lines of
`ConfigSyntaxTests` moved with their import line changed and not one assertion touched. That test file is
the asset that makes the document model and the schema table safe to build; spending any of it on a
tidy-up here would have been spending it early.

`ConfigLoader.defaultPath()` came across as `Config.defaultPath()`, which is the one judgment call in
the change. Where the config file lives is a fact about the config, not about the shell — it is
`$EMIRA_CONFIG` and `NSHomeDirectory()`, no disk touched — and the CLI will need it without being able
to depend on `EmiraShell`. The shell keeps locating in the sense that matters to it: opening, reading,
watching.

Two `trimmed` helpers were the pitfall worth naming. `TOML.swift` extends `Substring`, `CommandSyntax.swift`
extends `StringProtocol`, and they were same-module siblings until now. Both stay internal, so they end up
invisible to each other in different modules and no call site became ambiguous. `EdgeInsets` was the other
one: reading it from `EmiraCore` rather than from the same module puts it next to Foundation's
obsoleted-in-Swift-4 typealias of the same name, and the obsoleted one loses — but that is the compiler's
tie-break, not ours, and it is worth knowing it is being relied on.

Also recorded here rather than later, because this is where the direction became real: §10's "**No
preferences GUI.** The config file is the UI" is reversed. The narrower non-goal that survives it is the
one worth keeping — the file stays authoritative, the window is an editor of it, and no setting exists
that someone could not also type.

## Observations

`swift build` is clean and `make test` is green at the same 1005 tests: `EmiraCoreTests` went 649/31 to
567/28, and the new `EmiraConfigTests` is exactly the 82 tests in 3 suites that left it.

`EmiraConfig` imports `EmiraMotion` for `SpringParams` without declaring it — the dependency arrives
transitively through `EmiraCore`, which SwiftPM's module search paths make work. `EmiraCoreTests` has
always done the same, so this is the tree's habit rather than a new bet; declaring it would be one line
if the habit ever stops paying.

The roadmap row landed as **M6.5** rather than as a renumbering. A new milestone between M6 and M7 would
have pushed "Deluxe" to M8, and `M7` is referenced by name in four other places across these documents;
churning those to buy an integer is a poor trade.

The dependency `emira` (the CLI) *lost* here — it no longer links a TOML grammar it never called — is one
`emira config` will add back deliberately. That is not a regression when it happens: it was carried dead
and will then be used.
