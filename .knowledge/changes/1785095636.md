# A resize verb retires the recorded refusal and re-asks

> Change `1785095636` — 2026-07-26

## Goal

Two symptoms remaining after the previous change. `grow` against an immovable window left desktop
visible past the end of the strip until the next command, which then removed it with no animation. And
a second `grow` produced no motion, no AX set and no transition.

## Implementation

**Scroll targets are derived from the column widths a correction changes.** The column settled on the
correct width; the viewport did not, because a session keeps the destination computed before the
correction arrived. Measured on a three-column strip: the viewport rested at 316 with the strip ending
at 16 — 300 pt, the width the app refused. `handlePlacementCorrected` retargeted the width animator
only; it now also re-aims the scroll through `driveTransition`, the call `resizeFocusedColumn` makes
when a resize starts.

**A recorded refusal is a cache of one answer, not a property of the window.** The second symptom was
correct under the existing rules: the delta comes off the resolved width, so the second press
re-derives a question already on file, the recorded answer applies, `fromWidth == toWidth`, and the
command goes quiet. The premise is wrong — a window's limits usually depend on what it is currently
showing, so an app that refused 900 pt with one tab open may accept it with another, and nothing
observes that. `World.forgetCorrections` retires the record for the resized column so the verb re-asks.
If the constraint has lifted the window grows; if not, the refusal returns and springs the column home.

That also removes the need for a refusal-feedback mechanism. A staged bounce would be the first
animation in the system not converging on a real destination; instead there is an attempt, and the
spring home is what a failed attempt looks like.

## Observations

- Cost: one AX round trip and one cover per press against an immovable app.
- `forgetCorrections` is called only from the explicit resize verbs, never from a placement — a scroll
  must stay quiet, and the record's purpose is quiescence between commands.
- The delta arithmetic is unchanged and still why there is no dead zone; only the decision to consult
  the cache is reversed.
- The height axis still consults its record in one direction only.
