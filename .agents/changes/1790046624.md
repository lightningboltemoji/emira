# A closing window takes nothing out of a veil, and a hidden one leaves the strip

> Change `1790046624` — 2026-09-21

## Goal

Two artifacts on a machine where apps answer AX slowly, reported for Zoom, Excel and Outlook behind a
corporate agent that hooks their processes.

**A quit left a hole in the veil.** Ghostty and Zoom at half a display each, Zoom focused; ⌘Q Zoom and
Ghostty fills the strip — veiled, with a hole exactly where Zoom's window had been, which no later
repaint closed. The cause is in the mask, not in the arithmetic: `WindowRegistry.forget` drops a closed
window's number at once, so the plane meets it through `identify` as a window emira never managed, and
`Scrims.veils` subtracts any opaque pane behind a see-through one. Measured on a probe that reports
`.prohibited` — which LaunchServices does early in a quit — and then hangs: emira retires its window at
+0.06 s, and the window server keeps listing it on screen at alpha 1.00 until the process exits at
+3.04 s. Three seconds of a decline against a window that is not there, against a settle watch that
ends after `Scrims.settleQuiet` readings (~67 ms). Reproduced end to end, and also with no dying app at
all: an ordinary window emira never managed, ordered out after the mask was cut around it, leaves a
rounded-rect hole that survives indefinitely, because nothing tells the plane the stacking moved.

**A float that hid itself stayed hoisted.** Outlook's reminders window, snoozed: the panel keeps
standing in for a window that is gone, takes clicks, and goes transparent the moment a resize refilms
it. `World.isOnScreen` answers `true` for any float whose app is not hidden, so the core keeps naming
it; the only thing that ever takes a window off the strip unasked is `AXUIElementDestroyed`, which is
the app's to post and rides on a per-window registration that is a round trip a busy app answers
`.cannotComplete`. That refusal is rolled back so it can be retried — but only a scan retries it, and
`reconcile` scans only when it finds a stray. Meanwhile the standing liveness check is absence from
`.optionAll`, and an ordered-out window keeps its entry there for as long as its process lives
(`isOnScreen` false): measured, indefinitely. So a window can go away with nothing at all saying so.

## Implementation

**The mask skips what management has let go of** (`Scrims.departed` ← `WindowRegistry.departedNumbers`,
the same set a cover's base already cuts a hole for). Skipped rather than subtracted, which is the whole
decision: a decline is a claim about what lies *behind* a window, and a window on its way off the glass
will not be behind it a moment later — so the mask that ignores it is the one that stays right, and
nothing is owed a re-cut when it finally goes. Subtracting and correcting afterwards needs precisely the
event nobody has. What it costs is the length of a fade: a veil painted over a window that is still
showing its last frames, where the alternative is a hole that outlives it by the length of a teardown.

**The sweep is fanned out** (`WorldWatcher.onStackChanged` → `Scrims.recut`). A window emira never
managed arriving on the glass or leaving it moves the reading with nothing in the core to announce it,
and `Engine.settleScrims` only speaks when the *set* changes or the desktop settles under it.
Reconciliation already reads the whole window list every `reconcileInterval`, past the paint gate, so
noticing costs one set comparison and a re-cut that paints nothing when the mask comes out the same
(`ScrimWindow.setVeils` stops at the shape it would rewrite). Rejected: a watch of the plane's own,
which would be a second poller of one list and would have to learn `isPainting` for itself; and a longer
`settleLimit`, which lengthens a bound where what is wanted is a repair.

**Reconciliation asks about a managed window the server has stopped showing.** Off screen is not death —
the Dock, another Space and a background tab are all off screen and alive — so the reading buys a
question rather than a retirement, and `AXEnumerator.join` is the arbiter it goes to: that join already
retires only what AX has stopped listing *and* the window server is not showing, and treats an app that
described nothing as a timeout rather than an empty desktop. Capped per window at `maxReconcileRounds`
for `unaccounted`'s reason — a window on another Space is off screen for good and AX keeps listing it,
so without a cap it would scan its app every interval forever. Minimized and ⌘H-hidden windows are
excluded outright, both being facts the watcher already holds; emira's own placements never reach it,
since a parked column keeps its sliver on screen.

**The window-level registrations are re-offered every round**, beside the app-level ones that already
are. That is the gap that makes the question above necessary, and closing it is a dictionary lookup per
window on a healthy desktop: `watch(windows:)` is idempotent by id, and a registration that failed was
rolled back out of that record, so a re-offer retries exactly the failures.

## Observations

- **The alpha-zero shape is not covered.** An app can also make a window go away by keeping it and
  animating `alphaValue` to zero: measured, the window server then lists it as *on screen* at alpha
  0.00 and AX goes on describing it, so neither authority disagrees with the other and nothing here
  fires. The hoist keeps its picture, and a refilm — which a resize provokes — replaces it with a
  transparent one while the panel still takes clicks. Covering it wants either a new fact in the core's
  vocabulary ("the server has stopped showing this window") or a standing window-server read per
  hoisted float, both larger than this change. The measured cause of the reported ghost is the missing
  destroy notification, now repaired within a reconcile interval; if the reminders window still ghosts
  after this, that is the evidence that says it is this shape instead.
- A window minimized *before* the daemon started is not in the shell's `minimized` set, so it costs
  `maxReconcileRounds` scans of its app before the budget leaves it alone.
- A foreign window leaving the glass is corrected within one reconcile interval rather than at once
  (measured healed 0.8 s after the window went, bounded by 3 s). A foreign window that *moves* is still
  corrected only by the next set — the same standing error the feature already carries.
- Live-validated against the daemon: the hole (a veil drawn across a hung, retired window that used to
  cut it away), the heal after a foreign window closes, the hoist lifecycle, and a minimized window
  surviving four ticks untouched. The off-glass retirement itself is covered by the suite only — a
  probe cannot make the daemon miss a destroy notification from outside.
