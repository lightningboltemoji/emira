# A window in native full screen is off the strip, and so is nothing else

> Change `1793164261` — 2026-10-27

## Goal

Found while soaking the other fixes: put a tiled TextEdit window into native full screen and emira wrote to
it about 390 times in six seconds — every write corrected to the full-screen frame (`placementCorrected`),
answered `axFailed`, and placed again. And TextEdit's other two windows were retired (`windowDestroyed`)
while it was in full screen, then re-adopted with new ids as arrivals when it came out: a fresh focus
landed on one of them, the window the user had been in was parked, and the strip they came back to was not
the one they left.

Two facts behind it. The full-screen check runs once, at adoption (`WindowRole(… isFullScreen:)`), so a
window that goes full screen later is still a tile, and nothing about its size can be honoured — the column
clamps what it learns back to the strip's width and asks again. And `IMPLEMENTATION` §7 said a window on
another Space is "alive and AX lists all of them"; measured, AX's `AXWindows` lists only the windows on the
Space in front — with TextEdit in full screen it lists the full-screen window alone, while the window server
still lists the others, off screen. The join reads that as a departure.

## Implementation

**A reading, folded like the others.** `Event.windowFullScreen(id, Bool)` and `World.fullScreen` beside
`unshown`; a window in it does not participate in tiling and is not on the strip's screen. Entering is a
departure like a minimize's except that focus stays where it is — handing it to the neighbour would activate
another app and take the user straight back out of full screen. Leaving is an arrival beside the place it
left, focused, as a restored window is. Rejected: reusing the minimize pair, as ⌘H does — it would write
`isMinimized` on a window that is not in the Dock, and every reader of that flag would believe it.

**Read where it can be seen.** macOS posts nothing for either edge, but the window moves, and the watcher
already reads the frame of a window that moved by itself. A frame filling a display or its visible part is the
only shape full screen takes, so only that frame — or any frame of a window already in it — costs one more
attribute read (`AXFullScreen`, `ObservationSource.isFullScreen`); a window filled to the screen by hand has
the same frame, which is why the read is AX's and not the geometry's.

**An absence from an app with a window in full screen is no departure** (`WorldWatcher.isElsewhere`). That
covers both directions — the desktop windows while the full-screen Space is in front, and the full-screen
window while the desktop is — and leaves a close to its destroy notification and a death to its absence from
the window list, which are unaffected.

## Observations

TextEdit, live: entering full screen is reported 1.2 ms after the frame, no write reaches the window, no
window is retired across 5 s and a reconciliation round, the desktop and back again, and two windows each in
full screen at once; leaving puts the window back in its column under its own id, focused. Quitting the app
with a window in full screen still retires everything. Not exercised: a second display, a full-screen window
dragged between displays, and booting the daemon while a full-screen Space is in front — in which case AX
describes only that Space and boot adopts nothing else until the desktop is shown.
