# Virtual workspaces — the model and its verbs

> Change `1785109866` — 2026-07-26

## Goal

Add 36 addressable workspaces, each its own infinite strip, reachable by `focus-workspace`,
`move-to-workspace` and `move-to-workspace-and-focus`. They snap; the vertical animation is a separate
change.

## Implementation

Workspaces are a **fixed, ordered address space**: no creation policy, no deletion policy, nothing to
collapse — less machinery than the dynamic, per-monitor model `WorkspaceRef` originally described. The
domain is `1`–`9`, `0`, `a`–`z`, i.e. key order rather than ASCII order, so `1` is the launch address
and `prev` there clamps to a no-op as `focus left` does at the strip's start. Rank order and
lexicographic order now disagree in one place; nothing depends on the equivalence, because
`WorkspaceName` is `Comparable` by rank and every ordered view in `Workspaces` sorts by name rather
than by character.

**A switch is `Workspaces.focused` moving plus `emitPlacements`.** "Everything not on the focused strip
is parked" was already what `targetFrames` meant, and a park is a frame like any other, so the verbs
needed no new `Effect` and no change to `EmiraShell`. What they needed was state: each strip's scroll
offset and last-focused window, written on the way out and read on the way in.

Two hazards that are inert with one workspace were fixed while they still cost nothing:

- **One `ColumnId` space, not one per strip** (`ColumnAllocator`, held by `Workspaces` and passed
  `inout` to the two mutators that mint). A per-strip watermark makes column #1 on workspace `1` and
  column #1 on workspace `3` the same id, and `Motion.columnWidths` is keyed by a bare `ColumnId`, so
  an in-flight resize on one workspace would re-aim a column on another.
- **One park-ordinal run across the whole set.** With every window on every unfocused workspace parked,
  per-strip ordinals give two windows the same nub, breaking the ±2 pt identity join and the no-overlap
  invariant. Writing the test found a defect one level down: `ParkingLot`'s lane wrap moved only `x`,
  by one sliver, so lane 1 row 0 and lane 0 row 0 were inside the binding tolerance. `laneStep` (4 pt)
  fixes it. Unreachable before, since a lane holds ~107 rows.

`State.layout` became a settable computed projection of `workspaces.focusedStrip` — single storage, not
a second authority — which kept ~85 source and ~110 test references unchanged. Only `reconcile`,
`targetFrames`, `emitPlacements`, `teleportBehindCover` and `handlePlacementCorrected` stopped using
it.

## Observations

- Nothing is persisted across restart, so a daemon restart adopts every window onto the focused
  workspace.
- Per-monitor strips are the rest of M6; `State.metrics()` still resolves against `monitors.first`.
- `move-to-workspace` moves a window, matching `move-window`'s vocabulary.
  `move-column-to-workspace` is a later verb.
- A switch mid-transition abandons the open cover. Correct while the layers have nowhere to go; the
  animated slice reverses it.
