# a reproducible demo recording

> Change `1785220229` — 2026-07-27

## Goal

The README needs a clip, and a window manager's clip is the one artefact that cannot be regenerated
from source — it is a take, and a take is only as good as the run behind it. Every re-record after a
layout change would have been a fresh piece of improvisation with different timings, different
window counts and a different story. So the film gets written down: one script that opens the
windows, issues the commands, paces the pauses and captures the screen, and gives the same film
twice.

## Implementation

`.github/demo/demo.sh` is the choreography — `open`/`osascript` to make windows, `emira <verb>` for
everything else, and every pause a named variable at the top so a slower cut needs no edit. It
drives the real CLI over the real socket; there is nothing simulated in it.

**The caption overlay is a compiled AppKit panel, not post-production.** Burning text into the video
afterwards would need a non-stock dependency and a second source of timing to keep in sync with the
first. `caption.swift` is ~150 lines, built on demand with `swiftc` into a gitignored `.build/`, and
read one caption per line off a fifo `demo.sh` holds open — so the caption change and the command it
announces are the same two lines of script. Three of its window settings are load-bearing and one is
a consequence of emira's own design:

- **`.screenSaver`, above emira's `.floating` cover.** A caption drawn *under* the cover is captured
  into the reconstruction's base and freezes for the length of every transition — including the
  caption change that announces the next step, which is precisely when it must not freeze.
- **`.nonactivatingPanel`, ordered front regardless.** Every command in the choreography acts on the
  focused window; an overlay that could take focus would break the film it is describing.
- **`.canJoinAllSpaces | .fullScreenAuxiliary`,** because the Safari step is the one moment the demo
  leaves the desktop Space.
- Borderless with no subrole, so emira's own taxonomy resolves it to `.other` and floats it. The
  overlay is not a special case in emira; it is just a window emira declines to tile.

Every dimension in it is a base point size times one `scale`, defaulting to **3** and overridable
with `CAPTION_SCALE`. The film is downscaled to a small webp and the caption is the one element that
has to survive the shrink — the desktop behind it is allowed to get small, the text is not — so the
number that decides that is one constant rather than a dozen edited literals.

**The terminal is running when the script starts, because the script is being typed into it.** That
is not a precondition anyone can satisfy, so it is not one: the browser is checked and refused, the
terminal is handled by a `PREROLL` gap (5 s, printed) in which the invoking window is minimized —
which takes it off the strip like a close — and the film's four windows are all asked for over
AppleScript. Placing the preroll *before* the workspace switch is deliberate: a minimize is a
structural edit and opens a transition, and the first frame should not catch it half-animated.

**Recording is `screencapture -v` stopped by SIGINT, not `-V <seconds>`.** A duration is a number
somebody has to keep in sync with the step list, and it is wrong the moment a pause changes.
Verified that SIGINT finalizes the movie rather than truncating it: the `moov` atom lands at the end
of the file and AVFoundation reads back the expected duration and one video track.

**Preflight refuses rather than produces a bad take.** A demo app already running is the failure that
looks like success — the film records, and the focus walk in step 3 silently lands on the wrong
window because there were more than four. So it is checked and `--force` is explicit. The daemon
check asks for `debug`, which is a read and touches nothing.

The consume/expel pair reads as collapse-then-restore: `consume-or-expel down` swallows the next
column into the focused one (making a stack), `move-window down` reorders within it, and
`consume-or-expel up` extracts the focused window back into its own column.

**`webp.sh` is the other half: the `.mov` down to something a README can carry.** ffmpeg decodes,
resamples and scales; `img2webp` encodes the animation. Two tools rather than one because Homebrew's
ffmpeg carries the webp *muxer* without the libwebp *encoder* — and the split is the better shape
anyway, since `img2webp` exposes the per-frame quality and method that decide the size.

- **Decoding is sequential, never seeked.** `screencapture` writes variable-rate HEVC, and
  `AVAssetImageGenerator` answers `Cannot Decode` for over half of evenly-spaced requests into a file
  whose frames all decode fine in order (31 of 57 on a test clip; a sequential `AVAssetReader` got all
  73). ffmpeg's `fps=` filter reads in order and resamples to a constant rate, which is also what
  `img2webp`'s uniform `-d` assumes.
- **Measured, not guessed:** `-m 6` bought 4% over `-m 4` at roughly ten times the encode time, and
  `-min_size` bought nothing at all — same byte count, half again the wall clock. Both are left off.
- **Resolution is a ceiling and quality is the budget, rather than both being budget.** A third of the
  recorded pixels is all the clip needs — on Retina that is still two-thirds of logical size — so
  `SCALE` is fixed there and the remaining room under the 5 MB target buys quality instead. Measured
  on a 38 s take at a third: q75 1.6 MB, q85 2.7, q90 3.3, q95 5.9. Hence q90, the last rung with
  real headroom for a take that runs long, where q95 nearly doubles the file for very little.
- **`--fit` walks quality down (85 → 55) against `TARGET_MB`,** and quality is what moves because it
  is the only knob costing nothing structural. `FPS` is deliberately last: the demo's subject is
  smooth motion, and at 15 fps a 300 ms transition is four frames — the film would argue against the
  thing it exists to show. Re-encodes reuse the extracted frames, so an attempt is seconds.
- `SCALE` is written as a fraction (`1/3`) because it is interpolated straight into the ffmpeg scale
  expression, where it stays exact and never becomes a repeating decimal.

## Observations

- `new window` over AppleScript is the one step that depends on an app emira does not control, and
  every window in the film comes from it. A refusal is reported on stderr rather than swallowed,
  because a missing window does not fail anything — it just makes the focus walk land one column off.
  The standard suite's `make new window` is **not** tried first as a more-compatible spelling: under
  Ghostty it opens the window and *then* fails returning a reference to it (`Can't make class window
  id tab-group-…`, -2710), so anything chained behind it with `||` opens a second window every time.
  A command whose failure can still have had an effect cannot carry a fallback.
- Workspaces 1 and 2 being empty, and the invoking window being minimized during the preroll, are
  preconditions the script states and cannot enforce.
- The `.mov` is the artefact; GIF conversion is left to `gifski` and documented rather than scripted,
  since GitHub plays the movie inline.
- Not yet run end to end on a clean desktop — the pauses are first estimates and the cut is the part
  most likely to want tuning.
