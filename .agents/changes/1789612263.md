# Keep focus on a window while its sheet is up

> Change `1789612263` — 2026-09-16

## Goal

Closing a Ghostty tab with a process still running (`echo hello | less`, then ⌘W) puts up a "Close Tab?"
sheet. Cancelling it put focus back in Ghostty, but emira kept veiling the window as unfocused until focus
next moved somewhere else.

## Implementation

**Two AX facts, both measured on the live repro with a standalone observer.** Presenting the sheet posts
`AXFocusedWindowChanged` naming the `AXSheet` element. A sheet is a child of its window, not an `AXWindows`
entry, so the registry does not know it, and the observer reported `focusMoved(nil)`: `World.focusedWindow`
became `nil` and `scrimBindings` veiled every placed window, the sheet's own included. Dismissing the sheet
posts `AXFocusedUIElementChanged` and the sheet's `AXUIElementDestroyed`, but **no `AXFocusedWindowChanged`**,
so nothing ever reported focus coming back.

**The fix is to never let focus leave the window.** The sheet's `AXParent` is the window, and it compares
`CFEqual` to the `AXWindows` entry the registry bound, so a read can name it. A notification naming an element
the registry does not know no longer resolves to `nil` on the main actor, which cannot do IPC. It becomes
`WorldObservation.focusMovedUnmanaged(pid)`, and the watcher asks the app with `focusedWindow(of:)`: the same
read an activation costs, with the same `FocusIntent.newest` stamp (watcher case 6). That read now also
takes the focused element's `AXParent` and answers the registry's id for the element, or failing that for
its parent. A sheet on window 1 therefore reports `focusChanged(1)`, which the core folds as a no-op, and a
dismissal owes no report at all.

**The retry was forced by the first live run.** With only the above, the daemon still went to `nil`: the
read timed out. Measured five times with a lane-shaped reader under the same 0.25 s timeout: attempt 1
`kAXErrorCannotComplete` at +255 ms, attempt 2 answering the `AXSheet` at +283–288 ms, every time. Ghostty
stops answering AX while the sheet animates in. So an unreadable focus read is asked once more
(`maxFocusReadAttempts = 2`), still under the first attempt's stamp, before its fallback stands. The
fallback differs by caller. An activation named no window, so unreadable still says nothing. A notification
already said focus is on something unmanaged, so unreadable becomes `nil`, which is what the old synchronous
path reported and what keeps `World.focusedWindow` off a window the user has left.

Rejected: registering `AXSheetCreated` and each sheet's `AXUIElementDestroyed` to re-read focus when it
closes. That is more registration state, it leaves the window veiled for as long as the sheet is up, and it
still needs a read. Doing the read inside `AXObservationSource` instead of the watcher: that skips case 6's
stamp, so a slow answer could undo a focus command issued while it was out. Watching
`AXFocusedUIElementChanged`: it fires on every in-app focus move.

**The `ignore` rationale moved from sheets to dialogs.** `SystemFocusEvents`' doc, `PRINCIPLES.md` and
`ignoreStillAdmitsAWindowEmiraDoesNotPlace` justified admitting unplaced windows by "a modal save sheet".
A sheet now reports as its window, so the example is a dialog.

## Observations

Validated live with `EMIRA_TRACE=1`, over four ⌘W / Cancel cycles on a two-tab Ghostty window: focus was
window 1 at +0.1 s and +1 s into each sheet and 1 s after Cancel. The only focus events were four
`focusChanged(1)`. Confirming Close instead kept id 1 through the tab succession with no `nil`. The same
harness caught the symptom (`focused: null` during the sheet and after Cancel, both windows veiled) on the
build without the retry, whose timed-out read falls back to the original's `nil`. The original build itself
was not run under it. Only Ghostty's sheet was measured. Whether other apps' sheets stall AX as long, or longer than two timeouts, is untested.

Under `[focus] system-events = "ignore"`, a sheet that an app raises on a tiled window other than the focused
one is now judged as that window and refused. Before, it arrived as `nil`, which is always admitted. That is
`ignore`'s contract for tiled windows, and a sheet on the focused window, the ordinary case, is unaffected.

Every unmanaged focus report is now one lane round trip later than it was. The `nil` a brand-new window's
focus produces before its scan binds it can instead resolve to the new id, if the scan on the same lane
answers first.

A read on this path, like the activation read, is stamped only against emira's own focus requests. An
external report landing while a slow read is out can still be overtaken by that read's answer.
