# An accessory app's window is a window

> Change `1787889249` — 2026-08-27

## Goal

A menu-bar app with an ordinary window on screen was invisible to emira, permanently and silently. Ping
(`zip.tanner.ping`) sits in the menu bar and also opens a normal `AXStandardWindow` titled "General";
that window classified perfectly — `AXWindow`/`AXStandardWindow`, settable `AXMain`, readable frame,
layer 0, on screen — and never reached the strip, because nothing ever asked Ping about it.

Three gates all keyed on `.regular`: `AXWindowSource.applications()` left it out of the boot sweep and
every re-scan, `AXObservationSource.launched` never attached an observer, and `activated` ignored it
coming forward. The reconciliation heartbeat did see the window — an on-screen layer-0 stray nothing had
claimed — and could do nothing with it, because the stray-to-app lookup resolved pids through
`applications()`. So it re-found the same window every 3 s, spent its `maxReconcileRounds`, and gave up,
which is the failure mode the third invariant exists to prevent and the one a user cannot debug.

## Implementation

**The population question is split in two, and the wider half is paid for with evidence.**
`WindowSource` gains `target(for pid:)` beside `applications()`. The sweep keeps its `.regular` filter;
the per-pid lookup admits `.accessory`. The distinction is not which apps are manageable — it is whether
anything is pointing at one. `applications()` has to guess, and guessing wrong costs the sweep; the
stray path is asking about a window the window server has already put on screen and named the owner of.

Measured on an idle desktop before choosing: 3 regular apps, 43 accessory, 26 prohibited — and exactly
one accessory app owning an on-screen layer-0 window. Widening the sweep instead was the obvious
alternative and is what the numbers killed: a 15× fan-out on every scan and every retry to find one
window, six of the 43 being one Safari's `WebKit.WebContent` renderers, whose trees are precisely what
"never walk children" is about. The filter was never wrong, only too blunt to express "not speculatively".

`reconcile` calls it in the one place a target was previously unresolvable. That also deletes the
`known` memo: `applications()` swept every process on the machine to answer a question about one pid, so
the direct `NSRunningApplication(processIdentifier:)` is both narrower and cheaper. An app admitted this
way lands in `apps` and is registered on the next pass like any other, so the route is paid once rather
than every interval.

**`.prohibited` stays out of both**, since such a process cannot be activated at all and a column that
can never take focus is worse than no column. **Excluding our own pid moved from tidiness to
load-bearing**: the daemon is itself `.accessory`, so that clause is now the only thing between emira
and its own guides — `applications()` had the `.regular` filter in front of it and no longer does here.

**The protocol gets a default implementation** resolving through `applications()`, which is the honest
answer for a source whose app list *is* its whole world; only a source with a notion of apps it declines
to sweep needs to widen it. That keeps three of the four test doubles untouched and, more usefully,
means the stub that does override it is overriding it to model the exact asymmetry under test.

`launched()` was deliberately left alone. Relaxing it would close the up-to-3 s adoption latency for an
accessory app's first window, but it buys observers on 43 processes to fix latency on one, and the
heartbeat already exists to cover exactly this.

## Observations

**Validated against the live daemon, not only the suite.** Ping's window is adopted one reconcile
interval after boot, is focused correctly — `NSWorkspace.frontmostApplication` becomes Ping, `isActive`
and `AXFrontmost` both true, so an accessory app activates like any other — and tracks the strip with
emira's model and the AX frame agreeing exactly (x=1799 y=1129 w=900 h=548).

**Ping's window will not resize, and that is Ping's constraint, not emira's.** `AXSize` reports
`settable: false` and every set answers `kAXErrorFailure`, so `grow` updates the column's width override
while the window keeps its own size. The layout and the window disagree in exactly the way a
non-resizable window makes unavoidable; `place(at:)`'s one corrective pass then stops, which is the
documented "an app that refuses twice is asserting a constraint we are not entitled to override".
Whether the strip should represent a fixed-size window as something other than a column that lies about
its width is a real question and is untouched here.

**Only the discovery direction changed.** The removal direction still rests on absence from the whole
window list, and the off-screen half of the stray filter is what keeps the exemption from ever being
spent on the 40-odd agents that never show a window — pinned by a test, since the cost of losing it is
paid quietly on every heartbeat forever.
