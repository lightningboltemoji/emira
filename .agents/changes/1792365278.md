# The demo video: stand-in windows on a virtual display, cut in Remotion

> Change `1792365278` — 2026-10-18

## Goal

The README's film came from `.github/demo/demo.sh`: a shell choreography recorded with
`screencapture` off the main display, captioned by an overlay panel, and shrunk to a WebP. It filmed
whatever display you had, at its resolution, and needed preparation nothing could check: Chrome and
Calendar quit, workspaces 1 and 2 empty, and the terminal you ran it from minimized by hand during a
five-second preroll. The goal was a video in the style of Fiber's (`~/Developer/fiber/demo`: a tape,
a director, a Remotion studio with a moving camera) filmed at a fixed 1080p without changing a real
display's mode, with nothing in the picture but windows moving.

## Implementation

The layout is Fiber's, in `.github/demo` where the script was: `tapes`, `director` (its own Swift
package), `studio` (Remotion), `takes` untracked, and `make demo`, `demo-take`, `demo-render` and
`demo-studio`.
`.agents/DEMO.md` is the reference. What differs is all in where and how a take is filmed.

**A virtual display.** `CGVirtualDisplay` (private CoreGraphics; Chromium's test util is the source
of the declarations) was probed before anything was built. It gives a real display to WindowServer:
wallpaper, the menu bar, 60 Hz, listed by `SCShareableContent`. emira gives it a strip at once. It
goes away with the owning process. Changing the real display's mode (`.forAppOnly`, as the 1x probes
do) was the alternative; it would show the take on the user's own screen and can't make a 16:9
picture from a 16:10 panel.

**`screencapture`, not ScreenCaptureKit.** Every SCK display filter tried, including
`capturesShadowsOnly`, came back with no window shadows, and `CGDisplayStream` is obsoleted. For emira
that is worse than flat-looking windows: the overlay paints synthesized shadows on its stand-ins, so an
SCK film would show shadows switch on and off at every animation boundary. `screencapture -v` keeps
them, measured at the gap between two windows (142–157 against SCK's flat 213). It stamps no host
times, so the director opens each take with a magenta patch at a noted host time and finds its first
frame in the movie with `AVAssetReader`.

**Taking the desktop for a minute.** Only one daemon can manage the windows, so running daemons are
stopped with SIGTERM (whose cascade hands windows back) and this checkout's release daemon runs on
`.github/demo/emira.toml`, a copy of the author's look with its `[[display]]` blocks removed; the take
display matches none, so its `[layout]` has to be the main display's, not the built-in's. A fresh
daemon gives the main display workspace 1 with every existing window in it, which collides with a
tape's `focus-workspace 1`. Moving those windows with `move-to-workspace 9` isn't enough, because the
emptied 1 stays owned by that display and `focus-workspace` goes where an address lives, so each
other display also hands its emptied workspace to the take display with `move-workspace-to-monitor`.
Both were found by driving the daemon by hand before the director existed.

**What the director runs under.** Swift's async `main` drains the main queue with `CFRunLoopRun` and
calls `exit(0)` when it returns. Once AppKit owns the WindowServer connection, its run loop stops for
each event nobody dequeues. A daemon quitting is one such event, and the director exited silently
mid-handover, leaving no daemon running. The same starvation hid the virtual display's modes from the
director's own process while another process listed all 24. Both went away under `NSApp.run()` with
the director in a main-actor `Task`. Relaunching the user's daemon is awaited for a similar reason: an
`openApplication` still pending when the director exits never happens, which left no daemon after a
take that failed and exited at once.

**Stand-ins, not apps.** The first takes filmed real apps: Fiber on anthropic.com and Spotify, Claude
Code and Neovim in Ghostty. Their content was the problem twice over. It drew the eye from what the
video is about, which is windows moving, and it was most of the file: that take was 94 MB off
`screencapture` and its cut needed AV1's whole 10 MB. So each window is now a `standin`, a second
executable in the director's package: one window of one colour from the tape (`Color NAME RRGGBB`,
since `#` starts a comment), no title bar, and Fiber's traffic lights, moved by the same subclass of
AppKit's private frame view and set in the same rimmed glass capsule. A take of the same length is
about 17 MB. The render's master is 3.1 MB against 43, and the AV1 the cut was first encoded as fit
at CRF 10 (4.3 MB), where CRF 32 was 0.8 MB. Before the backdrop went flat, its drifting glows took
the same master to 10.6 MB. One process per window keeps it to an argument list, no IPC, and each is
quit like any app the take started. The colours are emira's green from the logo and more picked in
OKLCH against the author's solid Gold wallpaper (`#f0dfcb`): teal, plum and clay, deeper than the
green where they would wash out on cream. A process's `processName` doesn't change what
`NSRunningApplication` calls an app without a bundle; the path it ran from does, symlinks included,
so each stand-in runs through a link named for its colour, and the bar's names guide reads "green
plum teal" rather than "standin" three times. Real apps' launchers, `Type` and `Wait title` are gone
with them, and so is the `CLAUDE*` scrubbing, which only kept the filmed Claude Code from taking the
director's session for a parent.

**A stand-in opens bigger than its tile.** The take keeps the author's `window = "crop"`, which paints
a window's still at its own size while it moves and the scrim where the still doesn't reach. A
stand-in opening at 960×640 showed that scrim as a dark block on every open. Opened as big as the
biggest display, its first still is cropped down to the tile instead, and the opens are clean. A grow
of a window already placed (`grow`, fullscreen, leaving a stack for a whole column) still shows the
scrim for about half a second: a placed window is its tile's size, so that is its still, and a
stand-in held bigger would have its column widened to fit it. `stretch` hides it, but blows the
traffic lights up with the window for the length of the move; the scrim is the truer picture of
emira. Opening that big uncovered a race in emira: a window its reconciliation finds before the
window-created notice counts as already open and keeps its own width (`keepExistingWidth`), so one
take's Teal arrived as a column the whole display wide. The take's config gives stand-ins a window
rule starting them half wide, which wins over the kept width on either path.

**The studio** is Fiber's, with the window replaced by the display: a screen with rounded corners and
its own shadow, framed in display points, no mask. `Keys` shows each chord over the command
`.github/demo/emira.toml` binds it to, which the director records with the key. That keeps what the
old overlay's captions were for without a panel in the picture. A chord pressed again while its caps
are still up keeps them up and pops them, rather than fading them out and in at every press; the tape
writes a repeat as one `Key` step, whose presses are 160ms apart. The README's cut doesn't zoom: with
nothing to focus on, it holds the whole display at 93% of the picture. It opens on the wordmark
(`Backdrop`, drawn by `.github/logo/scene.ts`'s `frame(0)`, on near black), and the desktop slides
over it from the right like a column onto the strip, on a critically damped spring (the `emira`
ease), and slides on out to the left at the end, which makes the loop's seam the wordmark alone. The
shots say `offscreen: 'right'` and `'left'` rather than offsets worked out from the picture's size.

**Blurring a pan with a filter.** The camera's motion blur drew the display at up to 24 instants at
`1/n` opacity, added. Chrome composites in 8 bits, so each faint copy rounds, and the sum tinted the
cream desktop pink mid-slide; averaging whole pictures over each other at `1/(i+1)` instead drifted the
near-black backdrop from `0e1011` to `09090b`. A pan's blur is one picture under a Gaussian along the
pan, its spread a box's of the same length, in sRGB so a flat colour comes out unchanged; both colours
then measured the same blurred as still. Zooms and tilts keep the averaging. The script, its overlay
and its WebP encoder are removed.

**An animated WebP, lossless, at 800 wide.** The cut went to AV1 in WebM first, for GitHub's video
uploads, but an uploaded video waits for a click and doesn't loop, and an image plays inline, looped.
On the busiest four seconds, compared frame by frame with the render's own PNGs, an AV1 gained
nothing below CRF 10 and a ProRes 4444 master changed it by 0.2 dB, so the master stays JPEG frames
into H.264. As a WebP the 10 MB went quickly: lossy at q90 was 3.5 MB at 1200 wide and 30 fps, 6.0 at
1200 and 60, 9.5 at 1600 and 60, and q91 jumped to 14. Lossy also skips per-pixel changes under a
threshold that rises as quality falls, so a fade (a keycap leaving, a blur's tail) left stale blocks
behind it until that area changed again; 30 fps at q94 was clean, but 60 fps looked much better. At
800 wide, 60 fps lossless is 9.0 MB, with nothing to leave behind. Scaled that far down, a 1080p
render and a 4K one came out the same (44–47 dB between them), so renders stay at a cut's size. Each
frame lasts until the next one's time to the millisecond (17, 17, 16) rather than 16 throughout,
which would play 4% fast. The same measuring found the master untagged and encoded as BT.601, which a
browser plays as BT.709 (Green's `1c9b56` came out `128b56` from the WebM); it's BT.709 and tagged
now, so whatever reads it, ffmpeg included, reads it right.

## Observations

- macOS shows notifications on the display with focus, which during a take is the take display; one
  arrived mid-take (an AirPods handoff) and the take had to be redone. The director can't turn a Focus
  on, so DEMO.md asks for Do Not Disturb. Whether that stops the AirPods' "Moved to iPhone" pill,
  which isn't a notification, is untested; it showed in takes until Bluetooth was turned off.
- The film shows the author's environment: their wallpaper, which the colours depend on, and Bario on
  the take display (it follows the take's daemon over the same socket). Until the first stand-in opens,
  Bario names the frontmost app, which is the terminal the director runs from. A take on another Mac
  shows that Mac's.
- The race the stand-ins' window rule covers is emira's: an app whose first window is up before emira
  hears of it may get a column at that window's own width. Only seen with the stand-ins, which open a
  window the moment they launch, and not looked into further.
- Comparing encodes frame by frame needs them paired by frame, not by time: WebM's millisecond clock
  pairs a 60 fps file with the wrong frames of another during motion, which reads as losses that
  aren't there. Decoding both to numbered PNGs avoids it.
- The WebP is 9.0 MB of a 10 MB limit, so a longer or busier tape won't fit as it is: `encode.sh` says
  so rather than writing a file GitHub refuses, and WIDTH or FPS is the knob.
- 800 wide is less than a Retina README column wants; it's soft there next to the 1600-wide encodes.
- The flash's host time is when its commit was flushed, about a frame before it reaches the movie, so
  timeline times run up to a frame late. The camera's moves are offset by hand in the cut anyway.
- Only the one-other-display case was run. With several, each moves its windows to workspace 9, which
  the first of them is then showing, so the rest's windows travel there.
- Floating windows aren't moved off workspace 1; one on the main display would travel to the take
  display with the workspace.
- `.github/demo/out/` (the old film) is left in place; the `out/` the folder ignores covers it and the
  studio's renders alike.
