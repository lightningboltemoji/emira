# The menu bar item and the `.app` bundle

> Change `1785117028` — 2026-07-26

## Goal

Package emira as an application: an `emira.app` hosting the daemon, launch at login, quit from a menu,
and a status item showing the focused workspace. M5's last row.

## Implementation

**The app is the daemon.** One process, one bundle identity, no launchd job, no
`~/Library/LaunchAgents` plist, no separate GUI front-end.

- `emira-daemon` has been an accessory `NSApplication` since M2, because the overlay needs a window
  server connection and `CADisplayLink` needs a running app. Whatever ran under launchd would be this
  same process.
- TCC records a grant against the code signature of what runs. Accessibility is fatal-if-missing and
  Screen Recording gates the cover, so a stable `CFBundleIdentifier` inside a bundle is what allows a
  grant to persist. Ad-hoc signing identifies by cdhash, which changes every build, so macOS re-asks on
  every rebuild until a Developer ID signature replaces it.
- Quit stopping the daemon then requires no work. Under a `KeepAlive` agent it would require
  `launchctl bootout`.

**The status item is a display seam**, so `Runtime` gained `onStateChanged` rather than an `Effect` —
nothing about it changes state, the judgement `dumpState` got. It fires **once per drain** rather than
once per event: a command cascades through capture → raise → teleport → landings, and an observer
seeing each step would see states the user does not. Firing after the drain, outside `isPumping`, means
an observer only sees settled state. It fires unconditionally rather than on a change, because `State`
is large and comparing it at 120 Hz is a worse trade than letting the observer diff its own projection;
`StatusModel` is that projection, so a 400 ms scroll costs zero redraws.

**Both grants are checked at boot; only Accessibility is required to keep running.** Screen Recording
being non-fatal is correct for a grant revoked under a live daemon — exiting there would strand every
parked window at its nub. As a first launch it fails silently: the user gets AeroSpace parity and the
explanation goes to a stderr a bundled app cannot print. Two refinements: `smooth-transitions = false`
waives the Screen Recording requirement, since requesting it for a disabled feature is unnecessary; and
both grants are checked together, so a first launch costs one relaunch. This requires reading the
config before checking grants, which is safe because nothing in the config path touches a window.

## Observations

- `!` in the status title exists because a broken config changes nothing by design, so a typo and a
  no-op edit are indistinguishable from outside. The title carries the indicator and the menu carries
  the diagnostic. The same reasoning produced one alert on the fatal paths.
- A `reload-config` menu item was cut: the file is watched, so the button would advertise a step that
  does not exist.
- The CLI ships at `Contents/MacOS/emira` and nothing symlinks it, so there is one copy of the wire
  protocol on the machine. `$PATH` is a packaging concern for a Homebrew cask's `binary` stanza.
- Crash-respawn is given up. A respawn would rescue a desktop of parked windows via the boot scan. It
  can be added later as a bundled `SMAppService.agent(…)`.
- Signing is ad-hoc, so both grants are re-requested on every rebuild.
