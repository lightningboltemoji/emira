# Frost the desktop behind an unfocused window

> Change `1789536028` — 2026-09-15

## Goal

`[focus] unfocused-opacity` makes an unfocused window see-through, and on a detailed wallpaper that is
awkward rather than pleasant: every ridge, widget and icon behind the window competes with the text on
it, and the window reads as a smear over a photograph instead of as a surface. What a transparent
surface normally does about this — what macOS does for its own chrome — is blur what it is standing on.
So: `[focus] unfocused-blur`, a Gaussian in points over the *backdrop*, never over the window's own
content.

Flat beside `unfocused-opacity` rather than nested under a `[focus.unfocused]` table: nesting would
have to rename the key that already exists, and the two read as one material where they are — how much
of the desktop shows, and what the desktop showing through looks like.

## Implementation

**The blur is baked into the photograph, at film time.** The scrim plane holds one desktop photograph
per display and draws it back over each unfocused window through a mask. A blur is a property of that
photograph, so it goes on in `DesktopCapturer` as the film is developed: one `CIGaussianBlur` per film,
on the capture task, which is already off the main thread. The alternative was a `CIFilter` on
`ScrimWindow.host` — the idiom `SmearLayer` already uses — and it loses on two counts. Core Animation
clips filter output to the layer's bounds and feeds it nothing from outside them, which `SmearLayer`
buys room for with a pad; a scrim's layer *is* the display and there is no room to buy, so every edge
of the screen would fall off into transparency. And the mask over that layer is rewritten on every
focus change, where the photograph changes at most every two seconds.

`clampedToExtent()` before the blur is what keeps the display's own edges opaque. Without it the
Gaussian reads transparency in from past the screen, and since the host layer carries the colour while
the mask carries the alpha, a transparent edge is not a dark band — it is a band down every side of the
screen where the veil silently switches off and the window shows raw. `ScrimFrostTests` pins it.

The render is in the extended linear sRGB working space. Linear because a Gaussian is a weighted sum
and that is only the blur of actual light in linear light; extended because the default working space
is not wide, and a P3 wallpaper clips in a space that cannot hold it.

**The radius reaches the shell without passing through the core.** `Config.unfocusedBlur` is read in
`applyShellConfig`, the same path `Reconstruction.motionBlur` and `windowAnimation` take, and for the
stated reason: the core emits the same `ScrimBinding`s at the same veil under every radius, so the
effect stream is identical and the preference stays out of the vocabulary. `veil` is on the binding
because it *gates* the set — `scrimBindings()` returns nothing at all when opacity is 1 — and blur
gates nothing.

`Scrims` holds the radius and passes it down the `DesktopFilmer.film` seam rather than the filmer
holding it, because the plane is the thing a change invalidates. A new radius refilms every display at
once, outside `desktopMaxAge`: the throttle paces a desktop that *may* have changed, and this is a
photograph we know is wrong. That also means no second full-display image is kept per display to
re-derive from — the one photograph stays the only one.

## Observations

**A covered transition drops the frost, and this is visible.** Confirmed by burst-capturing the screen
during a slowed scroll: a see-through stand-in draws at `root.opacity = 1 - veil` over a base captured
with our own windows excluded, so for the ~500 ms a cover is up the wallpaper behind an unfocused
window has its detail back — the exact mountain ridge and desktop widgets the frost was hiding a frame
earlier. Two fixes were considered and both are worse than the artefact. A blurred backdrop layer per
stand-in, `contentsRect`-scrolled to where the stand-in has moved to, paints wallpaper wherever that
stand-in has travelled over a pin, a float or a foreign window the base holds — the backdrop lie the
whole decline machinery exists to prevent, traded in for a blur. Compositing the frost into the base
instead puts a full-display pass on the one latency in emira anybody can feel, and still blurs the bare
desktop nobody is looking through. Left as it is, and written down in `IMPLEMENTATION`.

**A neighbouring gap, found while reading the base filter and not chased.** The base excludes every
window of ours, scrims included, so an unfocused window that is *not* in a transition's scope appears
in it fully opaque — it loses its veil for the length of every cover, where a scoped one keeps it
through `Reconstruction.veil`. Same family as the above and older than this change.

**`aFailedFilmLeavesTheStandingPhotographAlone` was vacuous** and now is not. It drove the refilm
through `desktopMayHaveChanged()` one statement after the build, where `desktopMaxAge` throttles it out
and the filmer was never reached; it asserted that the photograph survived a film that never happened.
It goes through `setBlur` now, which is unthrottled, and counts the films.

**Every setting's `help` has to fit on one line** — `ConfigSchema.document` wraps at 96 columns and
`everySettingIsWrittenDown` asserts the document contains the help verbatim, so a sentence past ~94
characters fails the suite with a message about being missing from the document rather than about being
too long. Not introduced here, but it is what the first draft of this key's help hit.

**Untested on more than one display**, and on a machine with no Screen Recording grant the frost is
absent along with the whole effect, which is the degradation the plane already makes.
