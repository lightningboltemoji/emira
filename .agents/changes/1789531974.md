# The decline is a region

> Change `1789531974` — 2026-09-15

## Goal

A window the scrim should have made see-through was routinely left solid, and which window depended on
where it sat. On a three-column strip — `ghostty → font book → ghostty` — focusing the leftmost column
left Font Book fully opaque at rest, every time; focusing Font Book instead drew the Ghostty beside it
correctly, every time. Driving focus and `cycle-width` through eight resting states, six were wrong.

## Implementation

`Scrims.regions` asked the rule as one verdict over a whole window:

```swift
let backed = here[(index + 1)...].allSatisfy { !$0.pane.frame.intersects(binding.frame) }
```

Two things are wrong with that, and they are the same thing twice. The question is put in unbounded
desktop coordinates while the mask it guards is a raster clipped to the display, so pixels nobody can
see get a vote; and it is all-or-nothing, so one sliver of doubt forfeits a whole window. Neither is
exotic. A column at the edge of the viewport hangs off the screen, and its frame runs straight through
the **parking lot** in the corner where `Layout.park` stacks every off-viewport window — so the two
collide as a matter of course, out where the screen has already ended.

Measured live against the running daemon on an 1800-wide display, Font Book's binding at
`(1324, 47, 1345, 1102)`:

```
DECLINED by 'Ghostty' #1101 behind it; overlap=(1799,1105)..(2669,1149) = 870x44px
DECLINED by 'Safari'  #1375 behind it; overlap=(1799,1113)..(2659,1149) = 860x36px
```

Both overlaps begin at x=1799. **One pixel of each is on the glass; the other 869 are past the edge.**
Across the eight-state drive, every decline observed began at x=1799 — the feature's own parking
mechanism vetoing its own effect.

The rule as `PRINCIPLES` states it was never the one in the code: *a window is drawn see-through only
**where** the desktop is what lies behind it* is a claim about a region, and the code answered it as a
claim about a window. So the answer is a region now. Each window behind stamps its overlap back to
opaque *after* the scrim is painted, and the mask — already a painter's algorithm in `.copy` over the
window server's own ordering — carries it with no new concept. Both faults go together: the stamp out
past the screen edge costs nothing, because `CGContext` clips a fill to the bitmap and the bitmap is
the display. The clipping is not written down anywhere; it falls out of the shape.

The holes are appended *before* their scrim, because the list is built front-to-back and reversed into
painting order, which puts them back over it.

The rejected alternative was to keep the verdict and merely clip the question to the display. It is
half a fix on its own evidence: clipped, the Font Book overlap is still 1×44, and a window would still
forfeit 1.5 million pixels to forty-four.

### What the cover is told

`Scrims.veil(of:)` hands the cover one number per window, and a partial decline has no single number.
It reports the veil for the whole window, and the region the scrim declined is the one place that
cannot mislead: **the cover is the plane that does not need the decline.** A scrim declines where a
*window* is behind because its backdrop is a lone desktop photograph that does not hold it; the cover's
backdrop there is that window's own layer, drawn beneath this one, so a see-through stand-in shows what
is really behind it. More faithful than the decline, not less. The alternative — weighting the scalar
by backed area — buys a worse answer for more machinery.

### Validation

Third-process burst captures with the veil on and off, diffed over Font Book's on-screen region in six
vertical bands (mean |ΔL| in 0–255 luminance):

| band (pt) | 910–1058 | 1058–1207 | 1207–1355 | 1355–1503 | 1503–1652 | 1652–1800 |
| --------- | -------- | --------- | --------- | --------- | --------- | --------- |
| mean ΔL   | 24.19    | 23.64     | 23.28     | 22.64     | 20.92     | 21.45     |

Two captures taken with the veil on diff to 0.00 in every band, so the noise floor is nil and the
signal is the veil. It is even across the full width, out to the screen edge — including the band the
parking nubs stamp. Before the change this window measured 0: it was never drawn at all. The gradient
across the bands is the wallpaper's own, exactly the position dependence `1789528513` measured.

## Observations

- **The mask is never invalidated by the window server.** `Scrims.apply` runs only from `setScrims` and
  `setDisplays`, but it reads `stack()` — an ordering and a set of frames that change on their own. A
  foreign dialog opening in front, or a window settling after an AX set, changes the occlusion with no
  core event, so nothing repaints and the mask stays stale. Same class as the fault above: the shell's
  picture of the window server is sampled once and never re-asked.
- **`ScrimBinding` array order is unused.** The core sorts candidates through `stackingOrder(of:)` and
  documents the array bottom→top, but `regions` looks bindings up by id and walks the window server's
  order instead. Either the shell should use it or the core should stop paying for it.
- A `stack` now keeps the effect on whatever each tile leaves exposed, where before it declined
  wholesale. That is what the rule asks for and it never shows wallpaper where a window is, but the
  seam between a veiled sliver and an opaque body has not been looked at on a deep cascade.
- Untested here, as in `1789528513`: more than one display, and a window straddling two of them.
