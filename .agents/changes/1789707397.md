# The window server is late, so the plane waits for it

> Change `1789707397` — 2026-09-18

## Goal

Two ¾-width columns, focus crossing between them, and about half the time the veil lands where the windows
*were* before the scroll. The mask is cut against `CGWindowListCopyWindowInfo`, and every moment the core can
name to cut it is earlier than the moment that reading becomes true.

Measured, on one 1710×1107 display with two Ghostty windows, polling the window server every 2 ms against the
daemon's own trace (both on `CLOCK_UPTIME_RAW`):

| moment | uptime |
| --- | --- |
| cover on screen, both frames written | 174291.2642 |
| `axLanded(w1)` — where the re-cut fires | 174291.2664 |
| `windowFrameChanged(w1)` | 174291.2666 |
| **window server shows w1 moved** | 174291.2744 |
| `axLanded(w2)` | 174291.2670 |
| **window server shows w2 moved** | 174291.3087 |

So the server trails the landing by 8 ms for one window and 42 ms for the other, and the AX frame report is no
better — it also arrives before the server has the move. The re-cut at the landing therefore reads the old
desktop, and nothing reads it again: the echo-driven sets that used to blunder into a correction are gone, and
`windowSelfPlaced` only re-sends for a window emira will not write back.

## Implementation

**The plane watches the window server until it stops changing** (`Scrims.watch`). A set is painted at once and
then cut again every `settleInterval` while the reading keeps producing a different mask, ending after
`settleQuiet` readings with nothing new in them or at `settleLimit`, whichever comes first. A generation per
display means a newer set's watch owns the display and an older one's stops. A set that draws nothing is never
watched: there is no mask and no desktop to wait for.

This is `HoistPanels`' fence in another place — a hoist comes down on the window server's answer rather than
on the AX report that provoked it, for the same reason. The alternative, picking a later event, is what was
tried and is what failed: the dismissal is late enough under `smooth` and too early under `snap`, and any
fixed delay is a guess about an app's commit.

**What makes it affordable is the layer tree.** A re-cut writes each shape's path, and a path write does not
disturb an opacity animation (measured in `1789705895`), so the veil fading in over a moving desktop is
untouched by the corrections underneath it. A reading that produces the same shapes paints nothing at all:
`paint` compares against what the surface is drawing and returns early, which is what most re-cuts do.

**Paths are compared before they are written** (`ScrimWindow.setVeils`), for the same reason one layer up: an
equal `CGPath` is a new object, and assigning it would have the render server redraw a shape nobody can see
change.

The core's re-sends stay as they are. They are what starts a watch — the landing, the stillness of a window
emira does not place — and the watch is what makes the geometry true. Removing them would leave a display
whose writes land after its watch expired with no reason to look again.

Tests: `ScrimPlaneTests` gains a `ManualScheduler`, and three tests — a reading that changes is painted as a
`cut`, a watch that ends after `settleQuiet` quiet readings (and is never started for a set that draws
nothing), and a reading that keeps changing keeping the watch alive past that. Two existing tests moved their
occluder somewhere that actually changes the mask, since a repaint that changes nothing no longer reaches the
surface.

## Observations

Checked live, on the build this change makes, with the plane logging every paint's bounding boxes beside the
2 ms poll. Three focus changes back and forth, each one:

```
PAINT dissolve w2@442      the teleport set, cut against where the windows still were
PAINT cut      w2@1317     the watch, 12 ms after the window server moved them
```

and the final mask matched the final window-server geometry every time (w2 → 1317, w1 → −856, …). One round
caught a window mid-move (`w2@1279+410`) and then settled, which is the convergence the watch is for. The
logging was temporary and is not in the tree.

**The watch costs a window list per reading** — about 0.5 ms — for as long as it runs: at most
`settleLimit` / `settleInterval` readings, and in practice three or four. A desktop where something moves
every frame would pay it continuously, which is the same bargain `WorldWatcher`'s coalescing makes.

**`settleQuiet` is four readings, which is a guess, not a measurement.** It has to outlast the gap between two
windows of one app landing (34 ms here, two frames), and it does, but an app that commits its windows further
apart than four frames would end the watch between them. `settleLimit` bounds the other side at 0.4 s.

**Nothing here helps a window emira never wrote.** A dialog or Spotlight moving still leaves the mask as it
was until the next set or the next watch.
