# Filter linker noise; constrain `axValue` to `BitwiseCopyable`

> Change `1785175963` — 2026-07-27

## Goal

Remove the ~10 linker warnings emitted on every build, and give the compiler a constraint it can check
on a generic that reinterprets raw memory.

## Implementation

**Linker warnings.** A CommandLineTools-only install makes SwiftPM pass
`-F $(DEVDIR)/Developer/Library/Frameworks` (and a matching `-L .../Developer/usr/lib` for executable
products) on every link. That subtree exists only inside `Xcode.app`, so `ld` warns once per target.
The flags are SwiftPM's own: nothing in `Package.swift` removes them, and nothing we link lives there.
The `Makefile` filters stderr for `search path … not found` lines naming that directory only. stdout is
untouched, so `swift build` keeps its tty and its in-place progress line; a redirect rather than a pipe
preserves the exit status, so a failed build still fails the target. Requires bash for `>(...)`.

**`axValue`.** `AXValueGetValue` writes `type`-many bytes over its out-parameter regardless of what the
parameter holds, which is sound only for a type containing no references. The generic is constrained to
`BitwiseCopyable`, stating the precondition the C call already assumes; the compiler then checks
callers rather than warning about the raw-pointer conversion.

## Observations

The filter matches a path string, so a toolchain that spells that directory differently makes the
warnings reappear. It is not a blanket suppression — any other `ld` diagnostic still surfaces.
