# A tile outlives the pixels it was born without

> Change `1786148756` — 2026-08-07

## Goal

Under `guide.style = "preview"`, a window opened after boot never draws a preview. It takes the icon
placeholder and keeps it — through any number of transitions, long after its still is sitting in
`SurfaceCache` — until some *unrelated* window opens or closes, at which point it flips to a preview
and the newly opened window inherits the same trap.

The panel asked for a tile's content exactly once, in `rebuildIfNeeded`, on the frame the tile's
layer was built. But a window's pixels reach `SurfaceCache` only when the cover they were filmed for
comes **down**, which is strictly later than the frame in which the tile that wants them appeared —
the tile is built from the state that first lists the window, and the capture for that same
transition is still in flight. So the one moment the panel looked was the one moment there was
guaranteed to be nothing to see. The id set changing is what rebuilt the pool, which is why an
unrelated window opening fixed it.

Reproduced on the live desktop, and the prediction that isolates the mechanism was checked: open a
Ghostty window → icon; scroll back and forth so it is certainly filmed → still an icon; open a second
window → the first flips to a preview and the second takes the icon.

## Implementation

Content is now offered to **every tile, every frame**, and the tile decides whether that changes
anything. `RoundedLayer.carry` compares against what it already draws and returns; the comparison is
`CGImage` identity in the common case, because `SurfaceCache` hands back the same object until the
window is re-filmed.

The alternative — keep resolving once, and invalidate the pool when a still lands — was rejected. It
needs the cache to announce itself to the guide, which is a dependency the guide does not otherwise
have and which the *next* change (giving the cache a producer of its own) would have to widen. Per
frame, resolution is a dictionary lookup, which is cheaper than the notification would be.

That makes what a tile carries mutable, so `RoundedLayer` stops fixing it in `init`. One picture layer
either way, kept across swaps: the whole of the difference between the two `GuideContent` cases that
draw something is a contents gravity and whether it wears a mask, and `carried` is the authority for
both — it is what `fitPicture` switches on. A swap between two frames of the *same shape* gets no
`place`, so `carry` fits the picture itself against the shape already drawn; without that a still
arriving mid-dwell would sit at zero size until the strip next changed shape.

`rebuildIfNeeded` becomes `reconcile`, which adds and removes only the difference. The nuke-and-rebuild
it replaces was affordable when the pool was rebuilt only on a set change, but it threw away every
surviving tile's `drawn` cache along with its layer — a window opening made every other tile rebuild a
path it was about to draw identically. Tiles partition the strip and never overlap, so leaving an older
layer where it sits in the sublayer array says nothing; the invariant that matters is that they stay
below the ring and above the separators, and inserting `below: ring.layer` still gives both.

`reconcile` moved **inside** the `CATransaction`. It has to: `contents` is an implicitly animated
property, so a still landing over the icon that stood in for it would otherwise cross-fade over 0.25 s
— the same reason the transaction disables actions for everything else in the frame.

## Observations

The guide is drawn from a `SurfaceCache` whose only producer is a cover coming down
(`CaptureService.clearStore`), so this fixes *when* a window's picture is picked up and not *whether*
it has one. A window that has never been in a transition's scope still has no pixels, and every
preview is still as old as that window's last transition — visibly so, a video tile lags by seconds.
Giving the cache a producer of its own is the next change; it is the reason the cache↔guide seam was
left as a plain read here rather than grown into a notification.

`GuideTileTests` covers the tile's state machine against a detached `CALayer` — no window server, so
it runs in the suite; green at 1481 tests. `GuidePanel.reconcile` itself is **not** covered: it needs
an `NSScreen` and a real `NSWindow`. It is set algebra over the pool plus an insert, checked by
reading. **Nothing here was run against the live daemon**: the installed app is ad-hoc signed, so
reinstalling costs an Accessibility and Screen Recording re-grant (§12), and that was declined for
now. The end-to-end path — open a window, see its tile take a preview with no second window opening —
is unverified.

Not fixed, and separate: the guide reads as translucent over a moving backdrop. Its ribbon fill is
α 0.72 and what sits behind it for the whole time it is up is the cover (`Overlay`, opaque, one level
below), whose layers slide and then cross-fade out. Inside a tile that is ~3% transmission and
invisible; in the 3-point separation gaps and the ribbon's margin it is 28%, and measured against a
live scroll one gap drifted 65 → 52 in luminance while the tiles either side stayed bit-identical.
On a strip that fits inside `span` the tiles do not move at all, so a wash coming through the grid is
the only motion in the panel and reads as a shadow flowing across the previews. No alpha fixes it,
only fainter versions of it: the fix is an opaque base under the tiles, which is a look decision.

Also noticed while measuring: `emira config set <key> <default>` removes the key and leaves the empty
table header behind (`[animation.scroll]` with nothing under it).
