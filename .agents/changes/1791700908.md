# The scrim's settle watch waits out a cover

> Change `1791700908` — 2026-10-10

## Goal

`ASSESSMENT.md` P6. `Scrims.watch` re-reads the window list every 16 ms after each set, until four quiet
readings or 400 ms. A transition sends 2–3 sets. Each read synchronizes our own pending Core Animation
commit, which is one a frame while a cover animates. So the stall probe caught `Scrims.paint →
CGWindowListCopyWindowInfo` at 24–37 ms several times. Those were the transitions that ran at 102–113 fps.
Reconciliation and the arrival watch already yield to `isPainting`; the settle watch did not.

## Implementation

**`ScrimPlane.setCovered(_:on:)`, driven by `CompositingExecutor`:** `true` at `beginTransition`, `false` at
the start of the dismissal. While a display is covered:

- **A set is cut once.** The cut is needed, because the cover's stand-ins draw the veils it decides
  (`veil(of:)`, read by `refreshVeils`), and `applied` would otherwise lag the transition.
- **No watch is started.**
- **A watch already in flight is disowned** by bumping `settleGeneration`.

When the cover lifts, one watch runs for a display that holds a set. It finds out whether what moved under the
cover has settled, which it nearly always has.

**At the dismissal, not at `crossfadeDone` as the assessment suggested.** The fade is what reveals the scrim.
A mask left stale until the fade ends would be on show for its 220 ms.

**Not a yield to `isPainting`.** That would also skip reads on an *uncovered* display while another display
animates, and that scrim is in sight. Whether a display is covered is the actual condition.

**Validated live**, A/B on the same desktop with `EMIRA_STALL_PROBE=16` over 12–13 transitions each:

| | stalls in `Scrims` | per-transition fps |
| --- | --- | --- |
| before | 3 (33–35 ms) | 112–126 |
| after | 0 | 119–125 |

## Observations

- **The second half of P6 is not done.** That half shares one reading per run-loop turn, so `reconcile`'s
  list read would serve `recut`. `reconcile` reads `.optionAll` through `WindowListEntry`, and the scrim
  needs the on-screen list, which is the only one in z-order, through `StackedWindow`. Sharing needs one
  reader with one decoder, which is A7 (`WindowServer`). The cost it would save is one read per change in
  the on-glass set. That is rare and already off the paint path, because `reconcile` yields to `isPainting`.
- A set on an uncovered display while another display animates still watches at 16 ms and contends with
  that display's frames. Not measured: no transition on two displays at once was driven.
