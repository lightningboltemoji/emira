# Write whole points, and judge a landing by one threshold

> Change `1791700314` — 2026-10-10

## Goal

`ASSESSMENT.md` P8. Some windows were written twice per move with the identical frame. The executor called a
landing good within 1 pt (`AXExecutor.landingTolerance`). The reducer called a window placed within 0.5 pt
(`Engine.approximatelyEqual`). A window landing between the two was reported `axLanded` with no
`placementCorrected`, so no refusal was recorded and `isAlreadyPlaced` said no. The next `windowSelfPlaced`
then re-emitted the same `setFrame`. Ghostty did this on every move: asked for `x = -40.476`, it landed at
`-41`.

Two sources of fractional targets fed it:

- the layout's own arithmetic, `(span + gap)·p − gap`, which gives `.476` offsets with a 20 pt gap;
- `keepExistingWidth`, which stored `width / nominalArea.width` instead of `Extent.proportion(of:)`. A
  1320 pt window adopted at boot resolved to 1310.476 and was asked to shrink on every placement.

## Implementation

**Measured first.** Fractional frames were written to a TextEdit window over AX and read back:

- **x floors**: 300.6 → 300, −40.476 → −41.
- **Width rounds half down**: 800.5 → 800, 800.6 → 801.
- **y and height** came back with their own rounding: 200.5 → 201, 600.5 → 601.

Only an integral target lands exactly.

**`Layout.targetFrames` and `parkedFrames` round each frame with `Rect.rounded()`, and so does the pin write in
`writeTruthPlane`.** Every write, and every comparison against a target (`isAlreadyPlaced`, `alreadyRefused`,
the drag adoption, `handlePlacementCorrected`'s staleness check), now sees whole points. The presentation
plane is untouched. Layers still travel on `naturalFrames`, which is not rounded, so a spring is not stepped
in whole points. At rest a layer sits ≤ 0.5 pt from its real window, where the AX floor used to leave < 1 pt.

**Origin and size are rounded separately, not by edge.** Rounding by edge keeps gaps exact, but a rounded
width then depends on the fractional part of its origin and can sit a whole point off the unrounded width.
The correction machinery compares the written size against the layout's *question* (`uncorrectedSizes`, which
is not rounded) at 0.5 pt, in `shrankOffQuestion` and in the staleness guard. A full point of disagreement
there would make a cell-quantizing terminal's answer look off-question, and it would be re-asked forever.
Separate rounding keeps every written value within 0.5 of the layout's own value, so those comparisons hold
unchanged. The cost is a gap that can read 19 or 21 pt. The window server's own floor-and-round already
produced that.

**One threshold, `Tolerance.placement` (0.5 pt), in `EmiraCore`.** `Engine.approximatelyEqual` defaults to it,
and `AXExecutor.report` reads it through `Rect.isClose(to:within:)`. `landingTolerance` is gone. With whole
targets, a landing is either exact or at least a point off, so 0.5 versus 1 no longer changes which
landings are silent. What matters is that both sides read the same number. 0.5 was kept because the reducer's
size and scalar comparisons are already at 0.5, and they now sit beside it.

**`keepExistingWidth` uses `widthExtent.proportion(of:)`**, clamped to the nominal width, so an adopted window
is asked for exactly its own width back.

**Validated live** with the release daemon and the user's config (20 pt gaps, Ghostty, TextEdit, Finder,
Chrome): nine commands, focus, `cycle-width` and `move-window`. Every `setFrame` in the trace was whole-point,
no `placementCorrected` fired, and no `windowSelfPlaced` produced a write.

## Observations

- `AXAccess.sameFrame` still compares at 1 pt. It gates the writer's corrective pass, not the report. A6 (one
  tolerance namespace) is where it should join `Tolerance`.
- The quit cascade (`Cascade.frames`) is not rounded. Nothing reads its landings, because the daemon is
  exiting.
- Widths stay fractional in the layout and are rounded only at the write, which is where the ±1 pt gap comes
  from. Rounding resolved widths at the source (`Extent.resolve`) would make every gap exact, because
  positions would then differ only by whole numbers. But it moves every width-asserting test, and A4's
  geometry pass is the natural place for it.
