# `watch` streams the desktop

> Change `1790227177` — 2026-09-23

## Goal

Something other than emira should be able to show where you are. The motivating case is bario, a menu bar
replacement, drawing a row of column names like the names guide's inside the bar, and rolling it in when the
desktop changes. A bar is only one consumer, though. A script, a status widget or another bar wants the same
facts, and none of them should need emira to know it exists.

Before this change the socket offered no way to hear about a change: one request, one reply, then close. The
only read, `debug`, dumps `State`, which is the reducer's own shape and changes whenever the reducer does.

## Implementation

**A stream on emira's own socket, not a bus.** This is what niri's `event-stream`, sway's `subscribe` and
Hyprland's event socket do, and it is what bars already consume. Several alternatives were weighed and
rejected:

- *Calling the consumer* (`bario set …` from emira) couples emira to one bar.
- *Distributed notifications* are macOS's own pub/sub, but they give a late joiner no snapshot, a shell cannot
  reach them, and every post is broadcast to every observer.
- *A notify ping followed by a query* works, but it is two mechanisms for one job.
- *A shared broker daemon* is more machinery than either app.

The data is state rather than events, and that settles it. A consumer that starts late needs the picture first
and the changes after, and a snapshot stream gives it both.

**`DesktopStatus`, not `State`.** The schema lives in `EmiraProtocol` because third parties decode it. It is
versioned on its own (`DesktopStatus.currentVersion`), separately from `Wire.version`, and it is built in the
shell by `DesktopSubject` for `GuideSubject`'s reason. Per display it carries:

- the shown workspace and its layout kind;
- the columns, each named by `NamesModel.largest`, now `public` so both readers share one rule;
- each column's windows (id, localized app name, bundle, focused);
- the pins.

Beside the displays it carries focus (display, workspace, window, app, bundle), the workspaces that are
occupied or shown, and `moving`, which is `motion.needsFrames`.

**Discrete facts only.** No frame, no scroll offset and no title go out. A column's name is taken from
natural geometry, so a column still resizing cannot flicker its name. A focus change is therefore two lines:
the change, and then `moving` settling. A title change is none. That is `GuideTrigger`'s rule, one consumer
further out, and both are tested.

**Every key is always present.** A consumer that merges each line into what it had (bario's `exec` does)
would keep the focus that went away if a missing fact were simply omitted. `encode(to:)` therefore writes
explicit nulls where synthesized coding would drop the key.

**The publisher is a peripheral.** `DesktopPublisher` hangs off `onStateChanged` beside `Guide` and
`MenuBarItem`. It diffs what it publishes and hands a line to the server's watchers. It is not an `Effect`,
since it displays state and changes none. With no watcher, a drain builds nothing.

**`watch` is a read, like `dumpState`.** It is a `Command` case, so `emira --help` lists it. It is answered
out of band by `RequestRouter` from `Runtime.state` and is a no-op in the reducer where `dumpState` is.

`Wire.version` stays at 1, as it has through every verb added so far. The addition is readable by every peer
that could meet it: an old CLI never sends `watch`, and a new CLI sending any other verb to an old daemon still
works. What is lost is that a new CLI's `watch` to an old daemon reads as a malformed request rather than a
version mismatch. Bumping would instead make every other verb fail between those two builds.

**The transport has three rules, and each follows from every line being a whole snapshot.**

- **Latest wins.** A watcher keeps one line waiting, and a newer line replaces it. A line already begun is
  finished first, because a torn line is a broken frame. A write source is armed only while something waits,
  so a slow watcher never stalls the queue, which a blocking `sendAll` with a deadline would have.
- **Counted from the request.** `SocketServer.isWatched` counts a watcher from the moment its request is read,
  under a lock, so the main actor never waits on a queue that may be busy with a slow peer. Counting from the
  first line instead would lose a change that lands during the hop to main: the drain would skip it, and the
  new watcher would be left on a stale snapshot. Because the hop lands between drains, the snapshot the router
  sends is also what every other watcher already has, so nobody is sent it twice.
- **Leaving is heard at once.** A read on a watcher can only be the peer leaving. `poll` reports POLLHUP for a
  half-close and for a full close alike, as measured with a socketpair on macOS 27. A zero-byte `write` tells
  them apart: it fails with EPIPE only for a peer that has gone. A half-closed watcher (the way `nc` ends a
  request) keeps its stream, with its read source suspended. The CLI does not half-close.

A watch connection holds two dispatch sources over one fd, so the fd is closed by whichever cancel handler
runs last (`Connection.hold` / `drop`) rather than by the read source alone.

**The CLI** streams through `SocketClient.watch` with no receive timeout, since a desktop nobody touches can be
silent for hours. It prints each snapshot's bare JSON, flushed. When the daemon goes it exits 1
(`streamEnded`), which is what lets a supervising consumer restart it with backoff.

## Observations

- The daemon was not run for this change. The stream is validated by the suite, over real sockets. The first
  run on a live desktop should confirm the line rate during a trackpad scroll: `needsFrames` holds through the
  gesture, so it should be two lines, and the offset target is not published.
- `DesktopPublisher.screenName` resolves a display's name through `ScreenGeometry.monitorId`, so it needs
  `NSScreen`. It caches only answers it found. A display it cannot find is named by its number until one is
  found.
- A consumer's display filter is its own business. bario, for one, currently shows one row on every bar, so it
  will pick the focused display's strip.
- Titles are deliberately absent. If a consumer ever wants the focused window's title, it should be a separate
  opt-in, so that it does not turn every terminal `cd` into a line for every watcher.
- `emira watch` gives a bar no way back: clicking a name to go there would want a verb like
  `focus-window <id>`, which does not exist.
