# Read the config from `config.toml`

> Change `1789715004` — 2026-09-18

## Goal

The config was read from `~/.config/emira/emira.toml`, and the schema was pinned as `emira.example.toml`.
Inside a directory already named `emira`, and inside a repository of the same name, both names restated
their container. `config.toml` is what the XDG layout expects of a program's one config file, and
`config.example.toml` is the example of that file rather than an example of emira.

## Implementation

One literal in `Config.defaultPath()`, which every reader already goes through — the daemon, the CLI and the
menu bar all take their path from it, so nothing else had to move. `$EMIRA_CONFIG` is unaffected.

No fallback to the old name. A fallback is a second place the config can live, and it would outlive the
reason for it: the daemon would have to say which file it loaded, `config set` would have to choose which one
to write, and the diagnostic would name a path the docs no longer mention. Renaming a file once is the
cheaper ask.

The golden file moves with `git mv`, so its history follows it. Nothing reads the name at runtime: the test
that pins it builds the path, `make example` prints a `git diff` of it, and the rest are prose. The file's
bytes are untouched — the schema did not change, so there was no regeneration to review.

## Observations

A user on the old name loses their settings silently — an absent file reads as empty, which is how a fresh
install looks, so there is no diagnostic to notice. The release note carries the rename; the code does not.

`ConfigSyntax.swift`'s header still narrates that the schema document "used to be a hand-written block here".
That predates this change and is left alone, but it is the kind of sentence the pass exists to delete.
