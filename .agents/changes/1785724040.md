# A cover per display, and the gate that quantifies over them

> Change `1785724040` — 2026-08-02

## Goal

The third multi-monitor phase, and the risky one: give each display its own transition session (D7) and
state the teleport gate over displays rather than over the desktop (D8). What phase 2 left behind was a
regression rather than a rough edge — one core session covered every screen, so a scroll anywhere raised
an opaque cover **everywhere** and held it for the whole transition, freezing a video playing on the
other display and doubling the capture head to do it.

Because a session animates a viewport, this drags the geometry with it: `Motion.viewportOffset` becomes
one per display, and once it is, both plane's queries need a per-display supply. So the phase also
delivers the thing that makes a second display worth having — **each screen tiles its own shown address,
against its own working area, at its own scroll**. No new verbs: `move-to-workspace` already crosses
displays, because `Monitors.assign` leaves an address on whichever display holds it.

## Implementation

**`Motion` grows a `Viewport` per `MonitorId`** — that screen's offset animator, its session, and the
redirect count its deadline re-arms on — beside a `detached` one read and written only while no display
is attached. The rule for what stays whole-desktop is not "what was easy to leave alone": the frame
clock is one (D9), the `LayerId` watermark is one (so an id names one layer on one screen and the
per-frame call can stay untagged), and the displacement and column-width animators are one because they
are keyed by ids that outlive a display — §6's argument, that a window changing screens must not lose
the animator carrying it.

**That last choice is what `MonitorContents` pays for.** With the animators whole-desktop, "which of
these is this screen's" is a question `Motion` cannot answer, so `State.contents(of:)` supplies it and
both `advance` and the settle gate take it. Scoping `advance` is load-bearing rather than tidy: a
structural edit seeds a displacement the instant its command lands, and that seed is what its cover
raises onto — advanced under *another* display's tick it would decay away during this display's capture
head, and the edit would raise onto geometry it had already finished travelling to.

**`Workspaces` takes a supply, not a shown address.** `targetFrames` and `uncorrectedSizes` are handed a
`StripPlacement` per materialized address — the metrics it is laid out against and, for one on screen,
the offset its display's viewport is at — and `State.placements()` is where `Monitors` and `Motion` are
joined into that list. The container still knows nothing about displays, which is what phase 1 bought
and this keeps. Two things fall out of the supply rather than being decided again: the **park run stays
one cursor across every lot** (D5 — mirrored displays report the same frame, so per-lot cursors would
hand two windows one nub and break the identity join silently), and `naturalFrames` is asked for one
display's owned strips, because it is what one cover draws.

**D8 is one rule in one place.** The four phases still decide everything, but per display: an idle
screen's windows are written where its viewport rests, a covered one's at the scroll's end its cover is
travelling to, and a screen mid-capture or mid-raise writes nothing at all. `placements()` carries the
first two and `writeTruthPlane` holds back the third, so `reassertTruthPlane`'s four-way switch became a
per-window routing on the same four phases, exactly as the plan said it would. A held display still
contributes its share of `World.placedOnScreen` — what the last completed pass decided — because
`notePlaced` describes the whole desktop and a partial pass must not make it a lie by omission.

**`Effect.capture` gained a `MonitorId`, which §5 said it would not.** A per-display cover has to know
whose desktop *base* a head batch owes, and nothing else in the vocabulary can tell the store. Left
untagged the alternative is "take a base for every display with no open cover", which is correct and
keeps an ordinary one-screen transition paying a second base and a second `SCShareableContent` fetch on
any two-display machine — the exact cost D7 exists to remove. D10 is untouched by this: the still is
still display-independent and `captureReady` still untagged, so a window owed by two covers is marked in
both and one landing settles both.

**Filming and excluding are one instruction again.** Phase 2 had to separate them because a fan-out
handed every capturer the request list and only the first photographed it; with a batch going to exactly
one capturer — the one whose screen the cover is over — the windows a cover shows and the windows its own
base must not contain are the same set. Removing the parameter is not a regression to before phase 2: it
is the seam phase 2 predicted, moved. It also puts the still's scale where §8 says it belongs, since the
capturer that films is now the destination overlay's.

**The store keeps per-cover ownership of stills.** A window two covers show is filmed once per cover and
released by the last of them; a per-cover sweep would blank a layer still on screen on the other display.

**`Compositor` routes where it used to fan out.** A `[LayerId: MonitorId]` recorded at every raise and
extension is what lets the per-frame call stay untagged (D11), and a raise now fences on **one** surface,
so `coverOnScreen(m)` is owed by that display alone. `CoverPlane` stopped being a `CoverSurface`: a
composite of surfaces is no longer a surface once the cover calls name their display, and pretending
otherwise would have meant a plane whose `raiseCover` cannot say which screen it means.

**Two smaller seams moved with it.** `HoldTimer` keeps a deadline per display, and `Runtime.holdArmedFor`
a generation per display, cancelled by absence — the sync walks what the core says is in flight and drops
what is armed and is not. And `PointerFocus`'s rule-2 suspension asks the display **the hand is over**
(`World.monitor(at:)`), not whether any cover exists: a cover on the other screen says nothing about
this one.

## Observations

`Reconstruction`'s `intersects` filter is gone rather than generalized, and that is a deliberate limit
worth stating: a window whose pixels reach past its own display is covered on the screen its workspace
lives on, and its far half stays in the neighbouring desktop — visible for the length of the transition,
and jumping when the real window teleports. Every window emira *places* is inside one display's working
area, so this needs an app refusing a size hard enough to overflow, and the alternative (a session
joining a second display's cover) is the thing D7 exists not to do. D8's "visible on" is therefore read
as "owned by, plus any open session that has it in scope" — the second term is what phase 4's
cross-display move will need, and it is already there.

The frames-per-transition number is now per display, and a run of blits counts as a frame for **every**
cover that is up. A tick emits the layer frames of every cover with motion to make in one run, so that
is right in the ordinary case and generous to a cover that has settled but is still waiting on a
landing. Fixing it properly would need `CompositingExecutor` to know which display a `LayerId` is on,
which is exactly the routing D11 keeps in the plane.

`Cascade.cascadeEffects` still lays the quit cascade out against the acting monitor's metrics alone. It
mattered less while a second display showed nothing; now that one tiles, §6's "once per monitor over
that monitor's windows" is a real (if teardown-only) gap.

**Still owed: the visual check.** Two displays, a scroll on one, and the other's pixels staying live —
which no headless test can see. Worth watching for specifically: a window sent to the address the second
display shows should tile *there* (`move-to-workspace <that address>`), the second display's guide should
draw its own strip, and `focus-workspace` naming an address the second display is showing will still
yank it onto the acting monitor — phase 1's noted churn, which D1 fixes in phase 4 and which this phase
makes visible for the first time.
