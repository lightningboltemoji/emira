# A window kept out of capture is drawn as a card

> Change `1793164265` — 2026-10-27

## Goal

An app can take a window out of every capture — `NSWindow.sharingType = .none`, which is what a password
manager, an SSO or MFA prompt, or a corporate security tool sets on the window that asks for a secret. Such a
window is still on the window server's list, so the veil cuts around it like any other. But ScreenCaptureKit
does not refuse it: measured, it answers with an image the window's size and entirely clear (7 of 5,616
sampled pixels opaque, against 5,531 for the same dialog unprotected). Painted as a photograph:

- a hoist stands for the window with nothing. The panel is "revealed", shows nothing, and a click on it passes
  through to whatever is under it — the float stays buried, and the user clicks through apps to find it. This
  is the reported "it correctly cuts the veil, but we never actually hoist the window", reproduced exactly.
- a cover's stand-in for it is clear, and the base has a hole where it was, so the window vanishes from every
  transition it is in.

## Implementation

The window server says which windows these are: `kCGWindowSharingState` is `0` (`kCGWindowSharingNone`) for
exactly them. `SCKCapturer.grab` asks once per batch (`refusingCapture`, one
`CGWindowListCreateDescriptionFromArray`), films the rest as before, and hands each refusing window back as a
new piece, `.refused`, carrying its frame, its scale, its title and its app. The main actor draws it as a card
(`WindowCard`): the window's frame, rounded at the 12 pt floor every plane cuts an unread corner at, filled
with the window background colour of the current appearance, its app's icon over its title over "Hidden from
screen capture". It arrives as an ordinary `CapturedSurface`, so covers, hoists and peeks take it with no
change of their own. No corner reading: none was taken, and the planes' floor is the radius it is drawn at.

Considered and not done: a placeholder inside `HoistPanels` for a film that comes back `nil`. A `nil` film is
usually transient — a display going, a window closing — and the next look replaces it; a refusing window is
permanent and is not `nil` at all. And it would have left covers losing the window.

## Observations

A background app's protected sign-in dialog, floated by a `role = "dialog"` rule and buried under TextEdit:
before, the core said `covered`, nothing showed, and a click there landed in TextEdit; after, the card stands
over TextEdit and one click brings the dialog forward with the keyboard in it. A protected window on the strip,
full-width beside a full-width TextEdit, caught 0.25 s into each of three scrolls towards it by one script run
against each build: the baseline build shows wallpaper where it should be in 3 frames of 3, this one its card
in 3 of 3.

Not done: the base. A protected window not in a batch — a float standing in the open while the strip scrolls —
is left out of the display capture by the window server, so it is missing from the cover for the transition's
length. It is back the moment the cover comes down.
