# The stack is asked again

> Change `1789533187` — 2026-09-15

## Goal

An unfocused window would settle with part of itself left solid — sometimes a strip down one edge,
sometimes nearly the whole window — and stay that way. It survived every later event, so it read as
geometry rather than as timing. `1789531974` left it standing as an observation; this is it.

## Implementation

The mask is cut from two inputs and only one of them arrives as an effect. `Effect.setScrims` carries
the bindings; the physical stacking they are masked against is the window server's, read inside
`Scrims.apply` as `stack()`. `apply` runs from `setScrims` and `setDisplays` and nowhere else, so the
window server is sampled at moments chosen entirely by the core's event timing — and those are the
wrong moments. A transition's AX writes land *after* the core described them. The set is painted
against where the windows still were, and because the bindings do not change again, nothing ever
repaints it.

So the other input is asked for: `Scrims.restack()` re-runs `apply(current)`, and a cover coming down
calls it beside `desktopMayHaveChanged()`. That moment is when both facts have settled — the cover is
down because the transition closed, and the transition closed because the AX sets landed. Unthrottled,
unlike the photograph: one `CGWindowListCopyWindowInfo` and one mask repaint per transition, against a
full-display screenshot the throttle exists to ration.

Proving it was timing rather than geometry took one measurement. Against a single veil-off reference,
the same state was diffed before and after a forced re-apply that changed no binding and moved no
window — the core's frames, the bindings and the window frames were all identical across it:

| `focus right / focus right` | rep 0 | rep 1 | rep 2 | rep 3 |
| --------------------------- | ----- | ----- | ----- | ----- |
| bands uncovered, before     | 15/16 | 15/16 | 15/16 | 0/16  |
| bands uncovered, after      | 0/16  | 0/16  | 0/16  | 0/16  |

Fifteen of sixteen vertical bands of Font Book were drawn solid, and re-reading the window server with
everything else held fixed covered all of them. The noise floor — two captures taken back to back with
the veil on — was 0.00 in every band of every state, so neither column can be an artefact of the
window's own content changing. With the re-apply on cover dismissal, the *before* column is 0/16 in
eight consecutive states across the same drive.

The rejected alternative was to have the core carry the frames of every managed window, not just the
scrim candidates, so the shell could take occluder rects from the core and use the window server only
for z-order and for windows emira never placed. It is the tidier reading of "each authority for its
own", and it closes this particular race outright rather than at a chosen moment. It also does nothing
for the rest of the class — a dialog opening in front, a foreign window dragged across a scrimmed one —
because those are the window server's alone. Re-asking covers both, and is three lines.

## Observations

- **What re-asks is a cover coming down**, which every transition ends with, so the strip is covered.
  Nothing re-asks on a window server change that no transition caused: a dialog opening in front of a
  see-through window, or a foreign window dragged over one, still leaves the mask holding the previous
  reading until the next transition. The hook for that is an observer on the window server rather than
  another call site, and it is not here.
- `restack()` costs a window list and a full-display mask repaint. Per transition that is nothing
  beside the cover's own capture batch; on a display changing resolution under a burst it has not been
  measured.
- **`ScrimBinding` array order is still unused** — the core sorts candidates through
  `stackingOrder(of:)` while `regions` looks them up by id and walks the window server's order.
  Carried forward from `1789531974`.
