# An unanswered focus read is not an answer, and the veil keeps an anchor

> Change `1790046625` — 2026-09-21

## Goal

`Event.focusChanged(nil)` says no managed window holds the keyboard, and `State.scrimBindings` reads it
literally: with nothing focused every on-screen window is a candidate, so the whole strip is drawn
see-through — including the window the user is typing in. Two paths reach that from a fact nobody had.

**The app answers, naming something nothing has bound.** A window emira declines at the AX boundary
(`AXUnknown` and not settable as main — app chrome carrying an `NSWindow`) takes key focus; the read
resolves neither it nor its parent, so the answer is `.window(nil)`. Measured on a probe: focus `nil`
and both columns veiled 50 ms after the window appeared, and it rests there, because nothing re-asks
who has focus. `focus right` lifts it by re-entering the strip at the near end, which is what made it
read as a veil that would not come off.

**The app does not answer at all, and the shell invented the answer.** `readFocus` carried
`unanswered: .window(nil)` for this path: two attempts at `AXClient.defaultTimeout` and a timeout was
taken as "focus left every managed window". Measured on a probe that opens a window and then blocks its
main thread for 2.5 s — the shape of an app that is slow to be adopted: `nil` at +0.85 s, the whole
strip see-through until the window bound at +2.75 s. On a machine where Zoom and Excel answer AX slowly,
that is the veil that stays after a quit, and it is the same event that arrives late from an app still
tearing windows down, where the intent record cannot drop it as stale because emira's own refocus
already landed before the report was even posted.

## Implementation

**An unanswered read reports nothing** (`WorldWatcher.readFocus`). The element such a report names is as
likely a window arriving that nothing has bound yet as one emira will never manage, and only the app
tells the two apart — so with no answer there is nothing to pass on. It unifies the two call sites (the
activation path already dropped an unanswered read) and the `unanswered:` parameter goes with it. What
this gives up is the case the parameter existed for: focus genuinely left every managed window and the
app cannot say so. That trade is the point — a stale belief costs one window drawn unveiled and a
`focus left`/`right` that starts from where the user was, both corrected by the next focus report, where
an invented `nil` costs every window on the strip and has nothing to correct it.
`anUnmanagedFocusTheAppCannotAnswerForStillLeavesTheManagedWindows` is renegotiated on those terms.

**The veil keeps an anchor** (`State.scrimBindings` reads `focusedWindow ?? lastFocus`). `World.lastFocus`
is already the shelter the arrival path takes from the same routine `nil` (`Engine.arrivalAnchor`), and
this is its second reader. It makes *any* `nil` proportionate, invented or honest: a launcher holding the
keyboard leaves the window the user was working in opaque and every other veil where it was, rather than
turning the desktop see-through. Rejected: a repair pass in `reconcile` that re-asks the frontmost app
who has focus. It buys only the transient case — a genuine "focus is on something emira does not manage"
re-derives the same answer from the same authority — and with the anchor in place there is nothing left
for it to buy.

## Observations

- `World.focusedWindow` is still `nil` in those states and every other reader behaves as it did: the
  guide's focus ring clears, and the focus verbs re-enter the strip at the near end. Only the veil takes
  the anchor, because appearance is the one reader for which `nil` is a claim about every window at once.
- The anchor is a window and goes when the window does (`World.remove`), so a strip whose last focus has
  closed is veiled whole. Unreachable in practice: a departure hands focus to a successor.
- `resolveFocus`'s liveness probe is weaker than it reads. It drops a report whose displaced window has
  died, asking `AXWindow.isAlive` — an `AXRole` read — and that answered `true` for an app whose main
  thread was blocked for the whole exchange, which is how the invented `nil` above reached the core at
  all. It fails toward passing a report on; the anchor is what makes that cheap.
- Live-validated: the declined window taking focus (the set does not move), and the slow adoption, which
  now has no `nil` interval at all — focus goes straight from the old window to the new one as it binds.
