# IMPLEMENTATION.md as a contributor's guide

> Change `1785692460` — 2026-08-02

## Goal

`IMPLEMENTATION.md` had grown to 2,134 lines against a 17.6k-line codebase — a document longer than any module
it describes, and roughly one line of prose per eight lines of Swift. The cause is structural rather than
careless: there are 54 change files for 58 commits, and each one's `## Implementation` section had been folded
back into the document, so the file had become a transcript of every argument ever settled rather than a guide
to the system as it stands.

That has a cost the length alone understates. `.agents/README.md` already says where an argument goes — the
investigation, the rejected alternatives and the numbers belong to the change, which `git blame` reaches — so
the material was duplicated, not homeless. And a reader who needs to know *where a new effect goes* or *why the
raise is two steps* had to find it inside paragraphs about corner-radius estimation from alpha coverage, WebP
frame pacing, and why `brew style --fix` is not what runs in the release job. The document had stopped
answering the question it exists for.

## Implementation

**The keep/cut rule was "would a contributor break this?"** Kept: the four invariants, the three vocabularies,
the target graph and the boundaries each one enforces, the pump, the transition phase machine and its gates, the
state decomposition, the four animated quantities, the geometry invariants (two viewports, outer-gap-vs-strut,
corrections in `LayoutMetrics`, ids never reused), the AX identity model, and the seams a test substitutes. Cut:
every "the alternative was X and it fails because Y", every measured number that proved a decision rather than
constraining a future one, and the release/Homebrew/cask section, which had grown to 15 bullets about a workflow
file. Nothing cut was lost — all of it is in `changes/` and reachable from the code it describes.

**Two sections were replaced rather than trimmed.** The annotated directory tree had become a second copy of
every file's header comment, ~260 lines of it; it is now a map with one clause per directory, plus the naming
conventions worth recognising (`X`/`XSyntax`, `Model`/`Panel`). And the config section enumerated every key in
prose — which is exactly what `emira.example.toml` is, generated from the schema and pinned by a golden test —
so it now points there and keeps only what the file cannot say: the values/format split, the three hand-written
sections, the three rules about a file that won't parse, and `applyEnvironment`/`applyShellConfig`.

**Two sections were added, because the old document had no place for them.** §3 ends with a table saying where a
new thing goes and the rule for splitting a decision that needs both a system answer and a policy; §4 is the
event loop written out as a loop — `dispatch → FIFO → reduce → executor → syncTimeSources → onStateChanged` —
with the event sources and the five planes named. Both were derivable from the old text and neither was stated.

**Seven inaccuracies were fixed, all found by reading the code rather than the prose.** The spine diagram named
effects that do not exist (`raiseCover`, `crossFade`) and omitted the pointer and system planes entirely. §3
described the transition as `beginTransition` → shell captures, which is backwards: the core emits
`Effect.capture` per scoped window first, and `beginTransition` is what the *last* `captureReady` produces. The
directory tree listed `Resources/default-config.toml`, which does not exist, and omitted `EmiraCore/Rules.swift`,
which does. `EMIRA_TRACE` was documented as an existing trace flag and is implemented nowhere. `ReplayTests` was
listed as a suite and does not exist — the replay *property* holds, the golden-log harness was never built — so
that is now stated honestly in §8 and carried as open item 6. The suite list was missing eight real suites. And
`stripAnchor` was attributed to `World` when it is a reducer helper reading `World.lastStripFocus`.

The result is 813 lines. Every API name, protocol name, file path, constant and suite name in it was checked
against the tree; `make test` is green (1,264 tests).

## Observations

- **The pressure that produced this will recur**, since the natural move on finishing a change is to fold its
  reasoning back into the ground truth. The preamble now states the boundary as a test — "when a paragraph here
  starts explaining, it has drifted" — but that is a norm, not a mechanism, and nothing enforces it.
- **`PRINCIPLES.md` was not touched** and is now 606 lines to this document's 813, which is closer to the ratio
  the two were meant to have. It was not audited for accuracy in this pass.
- Three claims kept from the old text could not be verified from the tree, being facts about the window server
  rather than the code: the ~10 ms per shouldered window on the capture head, the ~2.5 ms window-list query, and
  the two-callback display-link fence. All are recorded in earlier change files with their measurements.
- The change-file corpus is now the only home for a large amount of reasoning, which makes `changes/` load-bearing
  in a way it was not while the document duplicated it. A change file being wrong or lost is a more expensive
  failure than it was yesterday.
