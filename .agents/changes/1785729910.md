# Hot-plug: a display set that changes under a running daemon

> Change `1785729910` — 2026-08-02

## Goal

Phase 5 of the multi-monitor plan. The shell built one overlay, reconstruction, capturer and guide per
display **once, at launch**, and nothing dispatched `Event.screensChanged` after adoption — so plugging
a monitor in gave it no cover, no guide and no capturer, and unplugging one left the core believing in
geometry that had gone. The core's half of D12 was the degenerate one landed in phase 1: with no
display attached the whole desktop is held detached, but a display that *left while others remained*
lost its workspaces to the first survivor permanently, so a lid close on a docked laptop scrambled the
arrangement and reopening it did not put anything back.

## Implementation

**`ScreenWatcher` is a source and nothing more.** It folds
`NSApplication.didChangeScreenParametersNotification` into one `AttachedDisplays` reading — the
screens, the flip line they were measured against, and the core's `MonitorInfo` for each. One read,
several consumers, which is the rule the daemon's boot read already followed and for the same reason:
`NSScreen.visibleFrame` is live, so a second read for the core's copy would let a Dock that moved in
between inset a cover by one number and its strip by another. The boot read is now the same value
(`AttachedDisplays.current()`), so there is one shape rather than a launch path and a change path.

**`syncDisplays` reconciles rather than adjusts.** A window frame, a base placement, a backing scale
and a `CGDirectDisplayID` are all fixed at construction, so nothing here can be *updated* — a display
is kept only when its `MonitorInfo` is byte-identical and the flip line has not moved, and is otherwise
retired and rebuilt. Rebuilding is the boring option and it deletes a whole class of half-updated
state; the alternative (a `resize(to:)` on `Overlay`, `GuidePanel` and `SCKCapturer`) is three more
things to get wrong on a path nobody exercises twice a day.

**The two containers stay, their contents move.** `Compositor.setSurfaces` and
`CaptureService.setCapturers` are the seams, so the executor and the runtime are wired once at launch
and never rebuilt. A retired surface drops the layers minted on it — an id from a departed display
names nothing, exactly as one from a closed cover does, or a later `setLayerFrame` would land on
whichever surface took its place — and its raise and dismiss generations are **bumped rather than
dropped**, so a fence or a fade still in flight on it is answered as superseded. A retired capturer
loses its base with it: a photograph of a screen is the one thing in the store that cannot outlive its
display, and a re-plugged id at a new resolution would raise its first cover onto the desktop as it was
two configurations ago. Stills are not per display and survive, minus the ownership the retired cover
held.

**`State.setMonitors` closes every cover, not only the departed ones.** The ground the strip stands on
moved, so nothing on any screen is travelling to where it now belongs — the same argument that already
makes a display change snap rather than animate — and the shell is about to rebuild the overlays those
covers were drawing on. The core is told **before** `syncDisplays` runs, so each dismissal reaches the
surface that raised it.

The important half of that is the exemption. `screensChanged` also arrives redundantly, and
`EngineArrivalTests.nothingReachesTheTruthPlaneWhileTheCoverIsStillOnItsWay` pins exactly why closing a
cover mid-raise is not free: closing it makes the display `.idle`, `reassertTruthPlane` then writes the
truth plane, and the windows move with nothing on the glass to hide them — the one thing the two-step
raise exists to prevent. So the teardown is gated on the report actually differing from what `World`
already holds, display for display and in order. The first shape of this change closed unconditionally
and that test caught it.

**D12's reclaim is a memory, never an authority.** `Monitors.detached` keys each departed display's
assignment by the id it will come back as. A survivor still owns those addresses meanwhile — so
`monitor(of:)` stays total and nothing else in the container had to learn about departures — and a
returning id claims them back through the same `claim` a `show` uses, with the same `repairShown`
behind it. That makes the reclaim unconditional on purpose: a display dispossessed by a returning one
falls back exactly as it would if the user had switched to that address by hand, so no new cascade is
possible. `unattached` stays beside it and answers a different question (what is the desktop showing
while *nothing* is attached), which has to be total where this only has to be right.

**One clock, re-homed.** `DisplayLinkDriver.retarget` invalidates and rebuilds rather than pausing: the
link belongs to the old screen, and one for a display that has gone never fires again. Unconditional,
because AppKit hands out fresh `NSScreen` objects on every reconfiguration and there is no identity
here to compare against. A transition in flight loses at most a frame.

**`startManaging` now dispatches the *current* reading**, not the boot one. Adoption can be held back
for as long as a broken config file takes to fix, which is long enough to outlast a hot-plug.

## Observations

**Nothing debounces.** macOS can report a reconfiguration two or three times as a display wakes, and
each one costs a rebuild of every touched display plus a placement pass. The reducer is total and the
placement diffs, so the extra passes are idempotent, but the NSWindow churn is real. Worth a coalescing
delay if it turns out to flicker — which is a thing only a running daemon shows.

**A rebuilt display loses a cover that was in flight on it.** The core closes the session (above) so
the state is honest, but the user sees a cut rather than a cross-fade. This is a display
reconfiguration; a cut is the right answer, but it has not been watched.

**`MonitorId` is `CGDirectDisplayID`, so the reclaim covers sleep, lock, clamshell and KVM and does not
cover reboot** — or, on some hardware, a genuine replug. The deferred `[[monitors]]` config needs a
stable key (display UUID or name) and this is not it.

**`detached` is never pruned.** An id that never returns keeps its entry for the life of the process.
Each is at most 36 names and the number of distinct ids a session sees is small, so it is bounded in
practice rather than by construction.

**Still owed: the visual check.** Plug a display in and out under a running daemon; confirm the new
screen gets a guide and a cover, that the old one's workspaces come back to it on replug, and that the
frame clock keeps running when the fastest display is the one unplugged.
