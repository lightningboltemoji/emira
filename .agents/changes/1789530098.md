# A window that places itself

> Change `1789530098` — 2026-09-15

## Goal

A window that resizes or moves itself was recorded and never answered. `windowFrameChanged` wrote the
new frame into `World` and returned no effects unless a button was down, so a video player restoring its
size on the way out of fullscreen, an app remembering a geometry, a sidebar sliding out — all left the
window wherever it put itself, indefinitely. The layout never forgot: the next command snapped it back,
which is what made it look intermittent.

Worse than not answering, a press could answer *wrongly*. The drag bracket ran from the mouse-down to
the mouse-up **plus** the wait for the window to go quiet (up to `dragSettleLimit`), and `Drag.armed`
survived that tail — so the first window to move in it latched as the drag's subject and `dragEnded`
adopted its size as the column's width and the window's height. Clicking a button that makes an app
change its own shape wrote a `widthOverride` the user never drew. With a *self-animated* resize the
frames kept re-arming the quiet timer, the settle ran to its limit, and what the column adopted was a
size the window was only passing through: an 800 ms 870 → 500 pt animation was adopted at ~700 pt.

Measured with a probe app — an `NSWindow` that resizes, animates, moves, fullscreens, hides and refuses
on command — rather than with a real one, so each shape could be isolated and repeated.

## Implementation

**`Event.windowSelfPlaced(WindowId)`**, emitted by `WorldWatcher.waitForStillness` when one window's
frame reports go quiet with no hand anywhere near them, and answered by `reassertTruthPlane`. The wait
is per window and has no bracket, which is what separates it from the settle it is shaped like: that one
waits out the last of a movement the user has finished making, this one waits out a movement still being
made. Nothing is compared in the shell — whether the window is where it belongs is the layout's
question, and a pass that finds it in place writes nothing.

**`Event.dragReleased`**, the mouse-up as its own event, demoting `.armed` to `.idle`. A hand draws a
size while the button is *down*; that is the interval a subject may be latched in, and the wait after it
exists only so an already-latched subject's frames finish draining. No new `Drag` case: a press that
latched nothing is indistinguishable from no press at all, and `.subject` is deliberately untouched.

**`World.refusedFrames`**, the termination rule. Without one the answer is a standing exchange: an app
that takes the size and not the place reports the refusal back, which is another self-placement, which
asks the same question. Measured at ~8 writes a second with no end — 187 writes in the 20 s sample,
against 14 after. Rejected a per-window budget, because a count is not the fact; what the core has is
`placementCorrected` telling it the app refused, and `handleParkCorrected` already states the rule for
the other refusal an app can make ("placing again would ask the identical question, so stop here rather
than trade writes with the app"). So a position-only correction records the frame and
`windowSelfPlaced` declines it. Keyed on the **question**, like `SizeCorrection`, so it invalidates
itself — the next frame the layout wants is a different one and gets asked. A pathological window
therefore costs one set per real event rather than one per report, which is the standard `axFailed`
already sets.

**`stillnessQuiet` is 120 ms, and the number is measured.** An app's own animation reports at the
refresh rate until its ease-out tail, where a frame stops rounding to a new integer size and the reports
stretch. At 60 ms the 800 ms case was answered once, cleanly, at the end — but 2.5 s and 5 s animations
both left gaps of ~70 ms and were re-placed mid-flight, writing the layout over an animation still
running and flashing the window full-size for a frame. The gaps plateau around 70 ms rather than growing
with duration, which is what makes a constant the right instrument; 120 ms is twice that. It is longer
than `dragSettleQuiet` because it is waiting for a different thing.

## Observations

- **A self-placement costs one extra no-op write when the layout's target is fractional.** The layout
  asks for `x = 525.68`, AX stores 525, the echo reports 525, and the next pass sees a 0.68 difference
  and writes again. The second write moves nothing, so it reports nothing and it stops there. Pre-existing
  arithmetic, newly visible because self-placements now run a pass.
- **`reassertTruthPlane` is desktop-wide, so `alreadyRefused` gates the event and not the write.** A
  refused window is still written by a pass some *other* window provoked. It converged anyway in the
  sticky measurement, but a desktop with two windows refusing their place is untested.
- **A window in native fullscreen is placed at ~60 Hz, and this change is not it.** The probe's
  fullscreen round trip shows `placementCorrected` → `axFailed` every 16.6 ms for the whole time the
  window is fullscreen, with no `windowSelfPlaced` anywhere in it: emira goes on asking a
  natively-fullscreen window for its tiled frame and the app goes on refusing. Separately, the round trip
  leaves the column full-width. Both want their own look.
- **An app hiding a window (`orderOut`, which is what Outlook does) is indistinguishable from closing
  it.** Held the `AXUIElement` across one: it answers `kAXErrorInvalidUIElement`, `AXWindows` drops it,
  and it leaves `CGWindowListCopyWindowInfo`. The window returns with a new `WindowId`, losing its
  column, width, float state and workspace. Nothing in the observation plane can fix that; re-binding a
  returning window to a recently-departed identity would be a feature of its own.
- **`AXTitleChanged` is still not observed**, so window rules are never re-evaluated. Unchanged here and
  already stated in `Rules.swift`.
- The probe lives outside the repo. It drives an `NSWindow` from a command file and logs every geometry
  notification with a monotonic stamp, so its timeline lays beside `EMIRA_TRACE=1`.
