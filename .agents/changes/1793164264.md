# A window rule can match what macOS says a window is

> Change `1793164264` — 2026-10-27

## Goal

Hoisting is for floats the user chose (`PRINCIPLES.md` §4): a rule's `float = true`, or `float on`. The
taxonomy's floats — every dialog, panel and popover — are macOS's, and never drawn back. That leaves one
kind of window with no way in: a dialog from an app that is *not* the one you were working in. A VPN's
sign-in, an SSO prompt, a background sync client asking for a password. `from-focused-app` fails for it by
design, no fact about its title or app is stable enough to write a rule against in advance, and once you
click back into your work it is buried for good — the veil still cuts around it, read from the window server,
but nothing stands in for it. "It correctly cuts the veil, but we never actually hoist the window, and I have
to end up clicking through apps to get it to the front."

The fix is not to hoist the taxonomy's floats — that is §4's line, and the reason for it stands. It is to let
the user choose a *kind* the way a rule already lets them choose an app.

## Implementation

`WindowRule.role`, matched exactly against `WindowArrival.role` — the snapshot's `WindowRole`, before any
rule overrides it. `role = "dialog"` with `float = true` writes the same explicit `true` any float rule
writes, so the window is floated by choice and everything downstream — standby, burial, the audit, the click
— follows unchanged. Spelled as `WindowRole` spells it; anything else is refused with the six names. A
metadata matcher, so it alone makes a legal rule and composes with the others (`app-id` + `role` for one
app's dialogs only). The generated document carries an example.

## Observations

A probe that never activates puts up a titled panel (`AXDialog`) over TextEdit's column while TextEdit is
focused, and TextEdit is then clicked. With the user's config: no hoist, the dialog invisible, and a click
where it was lands in TextEdit. With `role = "dialog"` added: the hoist is `standby` on arrival, `covered`
the moment TextEdit buries it with the dialog's content in the picture, and one click brings the dialog
forward with the keyboard in it.

`float toggle` over a dialog the taxonomy floats still tiles it on the first press — toggle flips what it
sees, and it sees a float. Left as is: with the rule in place there is nothing left to press it for.
