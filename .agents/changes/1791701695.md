# Reconcile strip membership once per event

> Change `1791701695` — 2026-10-10

## Goal

`ASSESSMENT.md` A3. `Workspaces.reconcile(tiledWindowIds:onto:)` was called from 27 sites in `Engine`. Each
site spelled out where the membership came from (`world.tiledWindowIds`) and where newcomers go
(`monitors.shown`). Most sat at the top of a handler or helper and re-ran it defensively in case something
earlier had changed membership. The call is idempotent, so this was safe. But nothing said which calls were
load-bearing and which were insurance, and every new handler had to remember the line.

## Implementation

**One definition, `State.reconcileTiling(insertingAfter:)`,** names the membership and the home in one place.

**One defensive call, at the top of `fold`, for every event but `.tick`.** Every handler now starts from
strips that match `World`. Ticks change no membership and run at the refresh rate, so they are excluded, for
A11's reason. The top of `fold` was preferred over a post-pass at the end of `reduce` because it also covers a
state a test builds by hand.

**Calls survive only where a mutation precedes them within the event.** Each call site was classified by what
runs before it in its event:

| Call | Kept or removed | Why |
| --- | --- | --- |
| `departFromLayout`, after `leave` | kept | the departure itself |
| `arriveOnLayout`, with the anchor | kept | the arrival itself; the anchor is why a membership mutator cannot reconcile for itself, because a newcomer opens beside the window focused *before* it |
| `arriveOnWorkspace` | kept | the arrival onto a rule-assigned workspace |
| `reassertTruthPlane` | kept | the fallback after unpin, deminimize and float→tiled when the newcomer cannot animate in; there it is the join |
| `screensChanged`, after `setMonitors` | **added** | `rehomePins` can evict a pin already on that side back onto a strip. Only the top-of-helper reconcile in `revealAcrossDisplays` / `reveal` / `reassertTruthPlane` used to catch it |
| 14 command handlers, `handlePointerEntered`, `beginTrackpadScroll`, `revealAcrossDisplays`, `revealAcrossWorkspaces`, `reveal`, `scrollReveal`, `teleportBehindCover`, `strandedGeometry`, `departFromLayout`'s entry | removed (23) | each is reached only from an event's entry, or after a call that already reconciled |

The membership mutations that the audit traced: `insert`, `setFloating` by rule and by verb, `remove`,
`setMinimized` both ways, `setPin`, `clearPin`, and `setMonitors`/`rehomePins`. `setAppHidden` has no caller
in the core.

The suite passed unchanged with the 23 removals, so no expectation was moved.

## Observations

- The reconcile now also runs for events that never reconciled before, such as `windowFrameChanged`,
  `axLanded`, `focusChanged` and pointer samples. At ten windows on three workspaces that cost is in
  microseconds. It is per event rather than per handler, so the count is about what it was, but it falls
  on different events. Drag-rate `windowFrameChanged` and trackpad samples are the hot ones. P7 already
  removed most of the former.
- A `windowCreated` that returns early because no display is known leaves the newcomer off every strip
  until the next event's reconcile. It is then appended rather than placed beside an anchor. That is
  unchanged in substance: the next handler's defensive call did the same.
- A new handler that changes membership owes `reconcileTiling` before it reads a layout. IMPLEMENTATION.md §6
  states this; nothing enforces it.
