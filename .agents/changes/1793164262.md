# A JVM's dialogs are windows, and its blocked frame is not a dialog

> Change `1793164262` — 2026-10-27

## Goal

Two classifier mistakes, both found with IntelliJ IDEA itself.

**Its undecorated dialogs were declined as app chrome.** Confirm Exit and Trust Project answer `AXUnknown`
with a settable `AXMain`, no title bar and a fixed size — the shape the classifier reserves for Zoom's toolbar
popups — so emira never managed them. An unmanaged window is one nothing brings back once it is buried: on
first launch Trust Project opened behind Safari and the IDE sat waiting on a dialog nobody could see, and a
dialog no rule could float is one no hoist could stand in for. The veil still cut around it, being read from
the window server — the report "it correctly cuts the veil, but we never hoist" is this exactly, for any app
that draws its dialogs this way.

**Its main frame, behind a modal, was classified a dialog.** AppKit derives the subrole from `canBecomeMain`,
and a modal turns that off: IntelliJ's frame answers `AXDialog` with `AXMain` unsettable for as long as Confirm
Exit or a passphrase prompt is up, while the prompt answers `AXStandardWindow`. Adopted then — a daemon
restart, or a reconciliation that re-adopts — the IDE floated and its prompt tiled, for good, the role being
read once.

## Implementation

**`AXUnknown` with a settable `AXMain` is a window whatever its shape.** The file already said a toolkit
growing its own AX tree answers `AXUnknown` for an ordinary window and that the settable `AXMain` is the half to
believe; the shape test simply ran first. It now does not apply to that pairing. Measured against what it
must keep declining: IntelliJ's Find Action popup answers `AXUnknown` with `AXMain` *not* settable, and stays
chrome; Zoom's toolbar popups answer `AXStandardWindow`, and the shape test still declines them.
`canBecomeMain` is read once, as before.

**An `AXDialog` with a full-screen button tiles.** Measured: a titled, miniaturizable `NSPanel` answers
`AXDialog` *with* a minimize button and without a full-screen button; an `NSAlert` with neither; IntelliJ's
blocked frame with both. Only a window that can be a full-screen Space's main window has the button, which is
a document window's trait. One more round trip, only for windows that answer `AXDialog`
(`WindowRole(… canFullScreen:)`, defaulted so every other caller is unchanged).

## Observations

Live: restarting the daemon with Confirm Exit up now adopts the IDE as `standard` and Confirm Exit as `other`
(before: the IDE `dialog`, Confirm Exit not at all). ⌘Q with the daemon running: Confirm Exit arrives, the
user's rule floats it, buried under TextEdit its hoist goes up, and a click on the hoist brings it forward
with the keyboard in it. Not measured: Electron's frameless windows, which answer `AXStandardWindow` and so
are still judged by shape (the screen locked before the probe for them could be read; `GAPS.md` keeps it
open). Nor a resizable `NSWindow` that is not a panel and refuses to become main: AppKit gives a resizable
window the full-screen button by default, so such a window now tiles where it floated — defensible, since it
offers full screen, but seen in no app here.
