# Reading a still's alpha without converting its colour

> Change `1794812568` — 2026-11-15

## Goal

Pricing `cover = "immediate-fresh"` showed that a film's dearest part was emira's own, not the window server's. Every
still is read three times on the way into the store — two corner blocks (`measuredCorner`), the hole test
(`measuredWhole`), and later the reduction — and the first two drew it into a device-RGB context. A still comes
back tagged with its display's profile ("Color LCD" on the built-in panel), so drawing it there colour-matches
every pixel: 14.3 ms of CPU on a 2700×2204 px Ghostty still, to read 80 alpha values. The window server and
replayd together spent about 5 ms on the film itself. And the hole test runs inline before each still is handed
to the store, in a batch that films one window at a time, so the conversion sat on the head of every cover that
waits on its stills.

## Implementation

One rule for every read, in one place: `CapturedSurface.context(width:height:drawing:)` builds the bitmap context
in the still's own colour space where that can host one and the device's otherwise — the rule `SurfaceCache.reduced`
already followed — and in ScreenCaptureKit's own layout, premultiplied BGRA (`byteOrder32Little`), with
`alphaByte` naming where alpha sits. The two reads moved off `byteOrder32Big` and index alpha by it, at the
context's own stride; the reduction now calls the helper instead of carrying its own copy of the rule — the
same `CGContext` call argument for argument, so the stand-in it paints is unchanged. Nothing here touches the
capture itself: stills are still filmed SDR (`dynamicRange = .sdr`, `.sdrImage`), which `1785549810` measured
against HDR capture and kept.

Both halves of "a copy" matter, measured on fresh stills (the conversion is cached per image after its first
draw, so re-drawing one still reads near zero whatever the context and hides the whole cost):

| hole test into                       | CPU per still |
| ------------------------------------ | ------------- |
| device RGB, ARGB (before)            | 14.3 ms       |
| the still's own space, ARGB          | 3.1 ms        |
| the still's own space, BGRA (now)    | ~0            |

Alpha is unchanged by construction — no colour space touches it — and checked on real stills rather than taken on
faith: over six 2700×2204 films, all 480 hole-test samples and all 442,368 corner-block samples were identical
between the old context and the new. `aStillReadsAlikeInAnyColourSpace` pins it for Display P3 and sRGB (drawn as
a copy) and grey with alpha (which no 32-bit context hosts, so it falls back to device RGB and converts).

## Observations

In the daemon, under `cover = "exact"` on the built-in display with two Ghostty windows, alternating builds
(before, after, before, after; 19 two-window covers each, driven by `emira focus` toggles): the raise moved from
a median 140 ms and 140 ms to 109 ms and 112 ms, while the base held at 59–61 ms throughout. About 14 ms a
window, as the benchmark said, and on every cover that waits on a still — all of them under `exact`, and the
windows no kept still fits under the other two.

- The measurements came from a standalone benchmark mirroring `SCKCapturer.grab`, `surfaceShot` and
  `SurfaceCache.reduced` against one window on the built-in display; the same pass priced the rest of a film. Per
  still: `SCShareableContent` ~9 ms wall back to back and 11–35 ms spaced out, ~1 ms of CPU all told (once per
  batch, so once per `immediate-fresh` refresh film); the screenshot ~20 ms back to back and 25–60 ms spaced out, ~5 ms of
  server CPU, no visible GPU change; the reduction ~4.5 ms. A ¼-size capture cost the servers the same as a full
  one — the price is per request, not per pixel.
- One content read per `immediate-fresh` round instead of one per film was priced and left: over 16 two-window rounds a
  pass, twice, it saved ~11 ms of a ~120 ms round and ~1 ms of CPU, against stretching how stale each later
  film's frame may be from nothing to the round, and a capturer that can stop between the shots of one batch.
- A lower QoS for refresh films, which inherit the main thread's, is untried.
