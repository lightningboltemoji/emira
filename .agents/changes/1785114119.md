# Distinguish an intended focus change from a backfilled one

> Change `1785114119` — 2026-07-26

## Goal

Closing the tenth Ghostty window could snap the strip across the desktop to reveal the first, with no
animation, overriding the successor `Engine.successor` had chosen. Reported from the same six-window
strip as the far-right close.

## Implementation

`Event.focusChanged` has one meaning in the reducer: focus moved and we did not move it, so snap to
reveal. macOS emits the identical notification when an app whose key window closes picks a replacement,
and that pick is arbitrary. The reducer's rule was correct; the input was not a report of user intent.

The two are separated by one fact: whether the window the report **displaced** is still alive. That
cannot come from the notification stream, because AppKit chooses a new key window synchronously while
the closing one is ordered out and destroys its element later, so `AXFocusedWindowChanged` normally
arrives before `AXUIElementDestroyed`. `ObservationSource` gained `isAlive(_:then:)`: one attribute
read (`role` — cheapest attribute with an answer; `frame` is two round trips) on that app's serial
lane, the price `AXObservers.activated` already pays to turn an activation into a window.

The other notification order costs nothing: once `windowVanished` has been handled the registry has
forgotten the window, which answers the question without a round trip. The same registry check runs
again when the probe returns, retiring an "alive" answer taken before the element was invalidated.

`EmiraCore` is unchanged. The echo of our own `.focus(successor)` arrives as an ordinary report and
lands in `reveal`, which redirects rather than snapping while a transition is open.

## Observations

- Failure directions were chosen. A busy app can time out and answer "dead" for a live window; the cost
  is one dropped reveal. Reading that timeout as "the window is gone" would drop a real window off the
  strip, so this asks about focus only and never synthesises a `windowVanished`. `windowVanished`
  remains the sole authority on a window's death.
- Loss is bounded at one report: a dropped report still updates what the next is read against.
  `WorldWatcher.focus` tracks reports rather than deliveries and is not cleared when its window dies,
  since a dead name there is the cheap evidence. A test pins that the watcher does not go deaf to focus
  after a close.
