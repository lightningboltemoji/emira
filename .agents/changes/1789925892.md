# A column under a pin no longer lifts the pin's veil

> Change `1789925892` — 2026-09-20

## Goal

Ghostty pinned left at 50%, two 40% columns on the strip, focus all the way right. The middle column has
30% of itself under the pin and 10% showing — and exactly that 30% of the *pin* was drawn opaque, a hard
vertical seam down the middle of a window that should have been uniformly see-through, sliding across it
as the strip scrolled.

`Scrims.veils` cut each mask as the window's silhouette minus **every** other window it intersects, and
that one subtraction was doing two unrelated jobs:

- a window **in front** must come out — the scrim surface is above everything, so drawing there would
  veil the wrong window;
- a window **behind** comes out because the photograph holds wallpaper where a real window is.

Collapsing them meant the decline fired unconditionally. A pin is raised, so a column scrolled under it
is behind it, so the pin declined over the whole overlap.

The rule's premise is that the effect belongs to the strip, and `strip` promises windows never overlap.
A pin breaks that promise from outside the strip: the strip is laid out *beside* the band (`contentArea`
excludes it) but is never clipped, so a column scrolled far enough keeps its width and runs under the
pin. The one case the rule assumed impossible is the routine consequence of scrolling with anything
pinned.

## Implementation

**Two subtractions, told apart by z-order.** `panes` already runs front to back, so `other < index` is
"in front". In front always comes out; behind comes out only where it is a window nothing is drawing
see-through. The rule becomes: *a window is drawn see-through where what lies behind it is the desktop —
or another window this set is also drawing see-through.* This reverses `1789705895`'s collapse, which is
what made the pin case wrong; the argument there ("z-order decides nothing") held only under the
no-overlap promise.

**The second clause is an approximation, and it is the smaller of the two errors.** Behind a see-through
window is the desktop *and* that window's own content at `1 − v`, where the photograph carries only the
desktop — an error of `v(1 − v)·(D − A)`, a quarter-weight difference at `v = 0.5`, and spread smoothly
because one continuous photograph covers the whole window. Declining is not the exact alternative: it
leaves the front window's own pixels where that blend should be, an error of `v·(F − B)`, plus a step at
the overlap's edge. Exactness was never available here — that would need a capture per window, refilmed
whenever anything behind anything redraws — so the choice was between two wrong answers and this is the
quieter one.

**The cascade's decline moves to the core.** Relaxing the rule would otherwise switch `stack` on, since
every unfocused tile is backed by another unfocused tile. It was never asserted anywhere: the cascade
declined as an accident of the geometry rule, which the core's own header already claimed as a design
decision ("the effect belongs to the strip, and says so") without any code saying it. `scrimBindings`
now declines a `stack` workspace outright — `showing(_:at:)` becomes `veiling(_:at:)` and answers `nil`
there, reusing the workspace lookup it already did, so it costs nothing. A cascade stops paying for a
window-server read and a path boolean per overlapping pair, and what a veil buys there was small anyway:
the tiles are all one size, so the overlaps are the whole of what says which is on top.

A pin is on no layout, so `world.pins` short-circuits ahead of the kind check and a pin beside a cascade
keeps its veil.

Rejected: telling the shell where the pin bands are, so it could treat a column's overflow as hidden
ground. It puts layout geometry in the plane that exists precisely to not have any, and it answers only
the pin case — a float over an unfocused tile has the same seam for the same reason.

## Observations

**Measured live, A/B on byte-identical geometry** (1710×1107, pin at 20–845, column at 73–1179, focus at
1199–1690, `unfocused-opacity = 0.5`, `unfocused-blur = 8`). Mean luminance down a 300 pt strip, swept
across the pin:

| x (pts) | before | after |
| --- | --- | --- |
| 30–70 | mean 30.4 → 31.1, sd 0.8–1.3 | mean 30.4 → 31.1, sd 0.8–1.3 |
| 80–200 | mean 36.82, **sd 0.00** | mean 31.4 → 36.1, sd 0.7–3.3 |

`sd 0.00` down 300 pt is the window's raw background with no photograph in it at all, and the step sits
between 70 and 80 — the column's leading edge at 73. After, the wallpaper's gradient runs through it
unbroken. The cascade decline was checked on the same daemon: three windows on screen under `stack`,
only the pin named.

**A float over an unfocused tile is now veiled where it was opaque.** The tile behind it is in the set,
so the second clause covers it. Over the *focused* tile — the common case — it still declines. This was
not checked live.

**Two see-through windows deep is not handled exactly.** If A is see-through over B, and B declines over
an opaque C, A is still veiled over that region: the photograph stands in for B standing in for C. The
fold that would fix it is cheap — accumulate the region opaque panes take out, back to front, and
intersect rather than subtract pairwise — but nothing on a real desktop stacks that way yet.

**`settleQuiet` and the watch are untouched**, and the shapes are still cut against a window server that
trails the AX landing by 8–42 ms (`1789707397`). A pin's veil now depends on the column *behind* it
being in the set, so a set that arrives while the column is still parked cuts one mask and the watch
cuts it again — the same convergence, one more shape.
