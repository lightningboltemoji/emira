# A pane the window server has not caught up with declines nothing

> Change `1789928789` — 2026-09-20

## Goal

With a pin holding the left half and two columns beside it, focus all the way right and then one step
left: the column takes focus and slides out from under the pin, and for a frame or two the pin's veil
collapses to a sliver — `1789925892`'s bug back for 25 ms.

Traced on one 1710×1107 display, pin at 20–845, the column at 354–1179 with 491 pt of it under the band:

```
 89.9ms  beginTransition + setCoverClearing(left: 845)
115.5ms  coverOnScreen → setFrame(w4 → 865), setScrims([w1], .dissolve)
115.6ms  cut w1[20..371]  | server: w4@354..1179      ← 825 pt of veil down to 351
119.9ms  axLanded(w4) → setScrims(.cut)   same stale reading, same shape, no repaint
141.0ms  watch → cut w1[20..845] | server: w4@865..1690
```

At the teleport the column is focused, so it leaves the set and counts as opaque — while the window
server still has it under the pin. The rule then declines correctly against a reading of the past. The
set describes the destination, the reading describes the moment before, and the mask is a third state
that was never true: the column goes opaque and moves in the same batch.

**It is visible because a pin's band is the one place no cover reaches.** `settleCoverClearing` holds the
cover off it so the pin stays live on top, which leaves the pin the only window on the glass with none of
the protection the cover exists to give against the server's 8–42 ms lag (`1789707397`). The reverse
direction never flashed: there the column *enters* the set and is never opaque-and-behind.

## Implementation

**The core names what it has written; the plane decides when to believe the reading**
(`Effect.setScrims(_:_:_:moving:)`, `Engine.movingWindows`). `moving` is the windows with a write in
flight, plus everything a cover is still carrying — `hasLayers`, which spans the cross-fade, not
`isCovered`. The plane records each named window at the frame the server was still reporting for it, and
a pane standing at that frame declines nothing: a decline is a claim about what is behind a window, and
this one is already somewhere else.

**A record is dropped the moment the reading changes**, which is the only evidence available that the
server has caught up — and the watch already re-reads until that happens, so the mechanism is the one
already there. A name is consumed by the first cut that records it rather than held, or a window read at
a new frame would be suspended again where it now stands for good.

**The watch's end is the backstop.** A write the server never shows — an app that refused the frame —
would otherwise be waited on for ever, so quiet or the deadline drops the whole record and cuts once
more with the declines restored.

Rejected, both measured against the trace above rather than argued:

- **Holding the set until the writes land.** The server trails `axLanded` (119.9 → 141 ms), so the set
  arrives later and is still cut against a stale reading. The flash shortens to 21 ms.
- **Letting only in-flight windows off.** The column stops being in flight at 119.9 while the reading
  stays wrong until 141. Same 21 ms.
- **Suppressing the decline for the whole display while covered.** Simpler, and it would work here, but a
  foreign dialog parked under a pin's band stays put through every transition on that display and would
  be over-veiled for the length of each one. Naming what emira actually wrote costs one set and has no
  such case.

Covering the band is not available: a pin must stay live and emira may not re-level a foreign window.

## Observations

**Checked live on this build**, same geometry, same daemon:

```
140.4ms  coverOnScreen → dissolve w1[20..845] | stale: [w2,w3,w4] | server: w4@-99..1178
```

The first cut is already right, and it is the *only* cut of the transition — where before there were two.
The reverse direction shows the expiry working: `stale` goes `[w4,w2,w3]` → `[w4,w3]` as the server
reports w2, then `[w3]` as it reports w4. The steady state is unchanged, sampled at the same points as
`1789925892`'s A/B (mean 33.7 → 36.1, sd 2.0 → 3.3 across the band).

Both halves were mutated: dropping the staleness test from `cuts`, and dropping the watch-end expiry.
Each failed exactly the tests written for it and nothing else.

**A parked window sits in the record until the watch ends.** It is named by the cover's scope, never
moves, and so is only dropped by the backstop — harmless, since a nub in the corner declines almost
nothing, but it is the common case for the deadline path rather than a rare one.

**`moving` is a per-display set on an effect that is sent often.** It is empty on a still desktop, which
is nearly always, and bounded by a cover's scope otherwise.

**Nothing here helps a window emira never wrote.** A dialog or Spotlight moving under a veiled window is
still read where the server last put it, and the mask is still late by the server's own lag.
