# The value model, and a score to measure it by

> Change `1787199660` — 2026-08-19

## Goal

`1787197038` fixed the scanner and left the model: every number was a `Double`, there were no date-times
and no inline tables, and a document was a flat `[String: TOMLValue]`. That flatness was not a shortcut —
it was the cause of the three defects where emira read valid TOML and produced the *wrong answer* rather
than an error. All of it is one change, because each piece needs something the flat model cannot hold.

## Implementation

**`Payload` gained the types the spec has.** `number(Double)` split into `integer(Int64)` and
`float(Double)`; `dateTime(String)` and `table(TOMLTable)` are new. Radix integers are read rather than
refused — `0xFFFFFFFFFFFFFFFF` was the reason they were refused, and `Int64` is the reason they need not
be. An integer outside `Int64` is named rather than rounded into a `Double` that would read back as
something the file does not say.

**A date-time is its own text.** Nothing emira has is a date, so the components are never asked for and no
`Date` is built — only that the shape is one of the four, and that the calendar admits it, so `1979-02-30`
is a mistake with a line number rather than an unreadable number. Shape decides that a value *is* a date;
the calendar decides whether it is a good one. Conflating those made a bad date fall through to the number
reader and complain about the wrong thing.

**Floats keep their type across a rewrite.** A parsed `1.0` re-spells as `1.0`, because `String(Double)`
always writes a `.` or an `e`. A *constructed* integral number is written as a TOML integer, which is both
the shorter spelling and the truer type for a count — so `emira.example.toml` is byte-identical and the
settings window still writes `damping-ratio = 1`.

**The document is a tree, and each table remembers how it came to exist** — declared, implied by a deeper
header, made by a dotted key, or written inline. Every rule about naming something twice is stated in terms
of that, and three defects fall out of having it:

- `[a.b]` after `[[a]]` resolves through the array to its *last element*, because one walk answers what a
  path means and it is the walk that descends.
- An element's index is a position in a list rather than a name in a document, so `[[a]]` and `[a] 0 = 1`
  no longer collide. TOML permits all-digit bare keys.
- A table declared twice, a name used as both value and table, and a dotted key reaching into a declared
  table are all refused. Duplicate *keys* already were; these are the same mistake.

**The dotted-path interface did not move.** `take`, `takeAll`, `takeArray`, `leftovers`, `span(of:)`,
`names(under:)` and `extent(of:)` are reimplemented over the tree with the same signatures, so
`ConfigSchema` (769 lines) and `ConfigDocument` are untouched. Storage changed; addressing did not. The one
addition is `value(at:)` — a non-destructive lookup `span(of:)` and `line(of:)` already wanted.

**An inline table is a table.** `a = { b = 1 }` installs a table in the document rather than a value
standing in for one, so the schema reaches `a.b` whether the file wrote the header or the braces. It is
built as a `TOMLTable` by the scanner too, so `{ a = {}, a.b = 1 }` is refused by the same rule that
refuses `[a]` twice rather than by a second reading of it.

## Observations

`toml-test` — the format's own suite — now runs, which is what the value model was blocking: its tagged
JSON cannot be emitted without the types. **703 of 709 TOML 1.0.0 cases pass** (210/210 valid, 493/499
invalid). The six failures are all malformed *UTF-8*: byte sequences no Swift `String` can hold, so
`parse(_ text: String)` cannot receive them. They are refused where the file is decoded — verified against
`String(contentsOfFile:encoding:.utf8)`, which is what `ConfigLoader.swift:82` uses. End to end, emira
rejects all six.

The suite found four bugs the hand-written tests had missed, each now pinned:

- `+0x1` was accepted. A radix integer takes no sign at all, not even a `+`.
- `[fruit.apple.texture]` after `apple.color = "red"` was refused. A header may *pass through* a table a
  dotted key made and only may not *be* one — the walk was enforcing the final segment's rule.
- `{ fruit = { … }, fruit.apple.texture = { … } }` was accepted. An inline table is closed.
- A run of one or two quotes inside a `"""` string was consumed and dropped instead of becoming content,
  so `""""one quote""""` lost both quotes.

The harness lives in the scratchpad, not the repo: it needs the corpus cloned, and vendoring ~700 files or
adding a network-dependent test target is a decision worth making on its own. Making it a `make` target
against a pinned checkout is the obvious next step if the score should stay honest.

Two places emira is deliberately looser than a general TOML library, both because no setting is affected:
a date-time is not normalised to RFC 3339 canonical form (`1987-07-05 17:45:00` stays as written rather
than becoming `…T…`), and a multi-line string keeps CRLF as written rather than folding it to LF. The
suite's own comparison normalises both, so the runner does too.
