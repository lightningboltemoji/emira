# The window that would not come down

> Change `1786252700` — 2026-08-08

## Goal

Pressing Save left a settings window that could not be dismissed. Escape did nothing, a double click on
the dim did nothing, and the scrim stayed over every display with the controls still tracking the
pointer — a desktop the user could not reach, from the one button most likely to be pressed.

`SettingsWindow.Outcome` carried both events on one callback: `.save(rendered:basedOn:)`, which leaves
the window up, and `.dismissed`, which does not. The callback was called `onClose`, and `StatusItem`
read the name — it wrote the file, then cleared `settings` and told the daemon the window was down. A
save therefore dropped the only strong reference to the window while its scrims were still ordered in.
AppKit owns a window that is ordered in, so nothing came off the screen; what went was the controller
behind it, and every route into it is a `[weak self]`. Escape reached `KeyableWindow.onCancel`, the
double click reached `ScrimView.onDismiss`, both closures ran, and both found `self` nil and returned.
The composition was still drawing, still hit-testing, and unreachable.

Two consequences travelled with it. `onSettingsVisible(false)` resumed the hotkeys while every display
was still scrimmed, so a chord would have rearranged a desktop nobody could see; and `settings == nil`
re-armed `⌘,`, which would have opened a second composition on top of the orphaned one.

Reproduced end to end before the fix — a harness holding the window the way `StatusItem` does, pressing
Save, then Escape and a double click in the gutter: the object deallocated on the save, the scrim stayed
visible through both, and the click was delivered to a live `ScrimView` whose controller had gone.

## Implementation

Three layers, because the failure mode is absolute — a scrim over every display that will not come down —
and one mechanism guarding it is one bug away from this again.

**The callback split.** `Outcome` is gone. `open(text:onSave:onClose:)` takes two closures: `onSave`
hands over text to write, `onClose` says the composition is off the screen. A caller can no longer be
told the window is gone while it is up, and the compiler is what enforces it — the shell's handler could
not be written as it was. This is also the honest shape of the boundary, which §7 now states as four
crossings rather than three.

**The ownership.** `SettingsWindow.presented` holds a reference to itself from `show()` to `close()`, so
being on screen is what keeps the object alive and no caller's bookkeeping can shorten that. The
reference the shell keeps is for talking to the window, and `dismiss()` is now public because ending a
composition by releasing it is exactly what must not work. Rejected: making the views hold the
controller strongly, which is the same guarantee with a cycle that only `close()` breaks — a window that
is never dismissed then leaks the whole composition rather than the one object, and the failure is
silent instead of impossible.

**The answer of last resort.** `onDismiss`/`onCancel` return `Bool` — whether there was anyone to ask —
and a `false` is not treated as nothing happening. `ScrimWindow.tearDownOrphans()` orders every scrim off
the screen. It sweeps rather than clearing the window that was pressed on, because the scrims are one
thing to the user and a display that keeps its dim has nothing left to press; that sweep is why the
non-host scrims are now `ScrimWindow` too (with `takesKey`) rather than plain `NSWindow`, which
`KeyableWindow` becomes. What an orphan loses is the teardown — the lift, the clock, the caller being
told — not the way out.

`close()` also guards against running twice. It was always reachable: `ScrimView` fires on every press
past the second, so a quadruple click in the gutter is three dismissals, and each one told the caller
again.

`DismissalTests` covers the two entry points without a window server in the way — scrims at zero alpha,
which leaves `isVisible` true and shows the runner nothing: the click threshold, that every press past
it asks again, that a live controller is asked and the window left alone for it to lift, and that a
dismissal with nobody listening clears every scrim by both routes. The end-to-end case — press Save,
have the caller drop its reference anyway, dismiss — was re-run on the harness by both routes.

## Observations

The orphan path is now unreachable by construction, so `DismissalTests` is testing a branch that should
never run in production. That is the point of it; the alternative is finding out through another stuck
desktop.

A composition that is live and one that is orphaned cannot coexist — the orphan requires the controller
to be gone, which `presented` prevents — so `tearDownOrphans()` sweeping unconditionally has nothing to
be wrong about. If a second composition ever becomes reachable, that sweep needs to ask each scrim
rather than assume.

`saved()` and `fileChanged(text:)` still arrive on the reference the shell holds, which is now
explicitly a talking reference. Nothing else in the shell can take the window down, and nothing does:
the daemon's own shutdown ends the process.
