# A closing window is cut from the base

> Change `1788408295` — 2026-09-02

## Goal

Closing a window could leave it in the cover's base, frozen, for the whole close-ranks transition and
the cross-fade after it. The window was still on the glass — macOS fades a closing window out after
the app has let go of it — but nothing cut it from the base, so the desktop photograph carried it
under the layers sliding over its old place.

Two things guaranteed it, either one enough on its own. `AXUIElementDestroyed` arrives the moment the
app releases the window, and `WorldWatcher.retire` drops the registry record *before* emitting
`windowDestroyed`, so from then on no id could be translated back to a window number. And the core's
close-ranks scope is derived from the workspaces' membership *after* the removal (`scopeUnion`), so the
departed window is not in it — correctly, since it has no layer to draw — and therefore not in the
list the base's exclusion was built from. The whole path from the AX callback to the capture request
is synchronous on the main thread, with one async hop before `SCShareableContent` is fetched, so the
base was photographed tens of milliseconds into a fade that lasts longer than that.

⌘Q takes the same route for every window of the app at once: `appDeparting` retires them when
LaunchServices says the app is going, well before any of them leaves the screen.

## Implementation

**"Still on the glass though its app has let go" is a display fact, so the shell holds it.** The core
is untouched: it has no business knowing window numbers or fade animations, and its scope is right as
it stands — a departed window owes a hole, not a layer. `WindowRegistry.forget` moves the number into
a `departed` set rather than dropping it, `adopt` and `rebind` take a number back out when it is bound
again, and `rebind` puts the number it leaves behind in: ⌘W on the selected tab of a group moves the
id onto the successor and the core never hears, while the closed tab's own entry fades on the very
rectangle the successor's layer slides over. A background tab left there is harmless — off screen, so
not in the on-screen list the base is built from — and reclaimed when it is selected again.

**A head batch hands the departed to the capturer as a hole and nothing more.** `SurfaceCapturer`'s
`includeBase: Bool` became `base: BaseRequest?`, so the extra exclusion is by construction only present
when there is a base to cut it from; a grow batch and a hoist film pass `nil` as they passed `false`.
`SCKCapturer` adds `base.departed` to the same `excludingWindows` list as the requests and our own pid.
The protocol's note that "the windows a cover shows and the windows its own base must not contain are
the same set" stays true for what is *filmed*; the departed are the one thing the hole needs beyond
that.

**Pruned by the window server, not by a timer.** A departed number the window list no longer carries is
gone for good, and the number is free for the window server to reuse. `WorldWatcher.reconcile` already
reads that list every three seconds and hands it to `WindowRegistry.pruneDeparted`. Against the whole
list rather than its on-screen half, because a background tab is off screen and still exists. Reconcile
yields while a frame is being painted, which only delays a release.

**Rejected: a grace timer on the registry.** A close animation is well under a second, and a timer
would have been simpler than a prune — but it is a guess about a length macOS owns, and the list is the
truth already in hand.

**Rejected: the core naming the departed window in the batch.** `Effect.capture` already allows a
`size` of zero "for a window the world has lost", so the reducer could have scoped it. It would then
owe an ack and be filmed for ~25 ms at the head of the transition, and the registry had forgotten the
number regardless, so the shell change was needed either way and the core one bought nothing.

**Rejected: pruning from the capture path.** `SCShareableContent` is the more precise authority, but
feeding numbers back from a per-display capturer into the registry inverts the capture plane's
dependency for a bound reconcile already provides.

## Observations

**A cancelled ⌘Q now costs one transition, not one reconciliation.** `appDeparting` retires an app's
windows on `.prohibited`, and an app that puts up a save sheet and is told to cancel keeps them; the
existing cost was that they sat unmanaged until the next reconcile re-adopted them. Now a transition in
that window also cuts them from its base, so they vanish for the length of that transition and reappear
at the cross-fade. Consistent with a layout that already believes they are gone, and rare, but visible.

**Minimize is the sibling not addressed.** A minimizing window departs the strip by the same
`departFromStrip` path and animates for far longer than a close, but the Dock draws the genie from its
own window, and whether that survives `excludingDesktopWindows(true)` is a question for the screen.

**Not observed on a display.** The mechanism is proved by the tests and the code path; the fix was built
from reading the event loop, and the ghost's disappearance has not been watched.
