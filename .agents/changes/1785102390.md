# A second window animation: `crop`

> Change `1785102390` — 2026-07-26

## Goal

Only the owning app can produce resized pixels, so a window under a cover shows a still of the wrong
size for part of a resize. The existing behaviour scales the still to the rect, which distorts text for
the length of the motion. Add `[animation] window = "crop"`: the still held at capture scale, anchored
top-left, so a growing window shows desktop through the space it has not filled and a shrinking one is
cut off right and bottom.

## Implementation

The two modes emit a **byte-identical `Effect` stream**, because `setLayerFrame` says where a window is
and never how to paint one. Everything that differs is downstream of `CapturedSurface.frame`, a fact
only the shell holds. So the feature is two frame assignments in `Reconstruction` plus one pure
function; `Engine`, `Motion`, `Effect` and `CoverSurface` are untouched, and a window-animation
protocol with two conformers would have no core-side surface to sit on. `Config.windowAnimation` is the
third value the reducer never reads.

**Anchor rule.** The still goes at its own size pinned to the rect's top-left, overflowing when the
window has shrunk past it (`Rect.anchoring(_:)`). Centering the grow needs `max(0, (rect − still)/2)`
and two cases. Top-left is where a window's own content is anchored, so the title bar and traffic
lights stay where the real ones are about to be. The cases meet continuously at equality, so an
overshooting spring or a mid-flight reversal crosses between them without the content jumping, and the
axes need no cases — a `consume` grows a window's width while halving its height, which a
`contentsGravity` constant cannot express.

**Corner radius is measured off the capture.** There is no public API for another window's corner
radius and a constant goes stale with the next macOS, but the shape is in the alpha. Measure the
corner's *area*, not its edge: the arc is tangent to the edge, so scanning the leftmost column for the
first opaque pixel answers about `r − √r` — 8.6 for a radius of 12, 28% low. A quarter-disc leaves
`r²(1 − π/4)` of its square uncovered and antialiasing conserves coverage, so summing the alpha deficit
over a corner-sized block inverts to `r` within a quarter-pixel independent of the rasterizer, and on a
squircle yields the circular radius enclosing the same area.

**Three layers**, because a `CALayer` with `masksToBounds` cannot draw its own shadow and a crop must
clip: `root` casts the shadow, `clip` rounds and masks, `still` draws at capture scale and overflows.
`stretch` stays one layer.

## Observations

The first version answered the intersection of still and rect and trimmed the still with a matching
`CALayer.contentsRect`. Two faults, neither reachable by a test of a pure function since both lived in
a Core Animation property assignment:

- `contentsRect` measures from the bottom-left on a non-flipped macOS layer, so a window losing height
  showed its bottom and pushed its title bar off the top.
- A trimmed still never crossed the clip's bounds, so the rounded clip had nothing to cut and the cut
  edge stayed square.

Both were fixed by removing `contentsRect` rather than correcting it: the still overflows and the clip
cuts. A width-only shrink hid the first fault (`fraction.height == 1`), so it took a `consume` to
surface.

`stretch` remains the default and is byte-for-byte the code M4 validated.
