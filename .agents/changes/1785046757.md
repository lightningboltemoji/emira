# The hole a spammed keybind opens in the cover

> Change `1785046757` — 2026-07-25

## Goal

Fix the reported artifact: scrolling the strip shows ~100 px of desktop, then the window appears
already correctly positioned and animates the rest of the way. Reproduces only when commands are
queued faster than a transition settles.

## Implementation

Two independent latency defects, both in the pure core.

**Scope grows on retarget, but too late.** The stills a widened scope requests take a capture round
trip (~36 ms measured, most of it `SCShareableContent`), and nothing holds the layers back meanwhile.
Under minimal-reveal scrolling the newcomer's leading edge sits one `column-gap` past the destination
the session was already aiming at, so the layers cross into it within a few frames of the press.
`Layout.sweptWindowIds` now returns the swept run flanked by the column outside each end. The head
batch is a fan-out whose critical path is the full-display base capture, so one or two extra window
stills add little; an extension costs a serial round trip landing mid-motion.

**The extend gate starves under a stream of interrupts.** `isReadyToExtend` required every outstanding
capture to be in. Under sustained spamming there is always one outstanding, so the gate never reopens
and the cover stops growing for the rest of the transition: a scoped window rides it with no layer.
Measured on a spammed `move-window`: 600 pt of exposed base, versus 130 pt for the plain late
extension. The gate exists because `extendCover` mints a layer id once per window, so naming a window
whose still is in flight spends its only chance at a layer; asking per window rather than per session
keeps that property and cannot starve. The raise keeps its all-or-nothing gate, which is about the
base.

Neither was reachable from the existing suite: every scenario harness acks `Effect.capture`
synchronously, so a hole living between a `capture` and its `captureReady` cannot exist. New tests
drive a frame-stepped world where an effect answers a fixed number of frames later, and measure the
widest band of viewport a window wants to occupy with no layer. That reproduced the report: 130–140 pt
spammed, 0 pt spaced out.

## Observations

- No fixed lookahead is a guarantee; the residual is bounded by test rather than removed. A **scroll**
  or **resize** moves the viewport over a fixed column order, so the shoulder is the column arriving
  next: no hole at any capture latency, swept to 500 ms, past the capture plane's 250 ms deadline. A
  **structural edit** re-orders the strip and scrolls it, so a column reaches the edge earlier; the
  runway is about one command interval, ~2× the measured 36 ms batch at above key-repeat rate, and it
  degrades into a narrower hole rather than a cliff.
- The report said "only going left". The strip is mirror-symmetric and the harness reproduced both
  directions to the same tenth of a point; the reporter re-checked and agreed.
- Frames-per-transition, capture-head latency and RSS were not re-measured for this build.
