# A window its app stopped drawing is off the screen, and a window it keeps unbound blocks nothing

> Change `1790137481` — 2026-09-22

## Goal

Outlook's reminders window, floated by a rule, still ghosts after `1790046624`: snooze a reminder and a
picture of the window stands over the tiled window behind it, often transparent, and a click on it makes
it vanish. That change's own observation predicted this outcome, and a probe reproduces it end to end on
the live daemon.

**The window is alive and not drawn.** Measured with a probe app whose small window floats by the same
rule, two ways of putting a window away:

- `orderOut`: AX posts `AXUIElementDestroyed` at once and stops listing it; AppKit fades it over ~0.3 s
  (alpha 0.48, then 0.0008) before the server takes it off screen. emira retires it at the snooze.
- A fade to alpha 0 and kept: the server lists it `on=true, a=0.0` indefinitely, AX goes on describing
  it, and nothing is posted. The core keeps the float on screen (`World.isOnScreen` asks only
  minimized/hidden), the snooze's focus hand-back buries it, and the hoist goes up — for good.

Both halves of the report followed. The picture is transparent where the window changed size while
invisible, since the hoist refilms on a size change and the film is of a window at alpha 0; it is an
opaque stale still where it did not. The click is not a failure but the hoist working: `hoistClicked`
focuses the invisible window, the float is then in front, and the panel conceals. An alpha-0 window is
click-through (measured: the click passes to the window behind it), so after that nothing on the glass
answers. With focus now on the invisible window, the tiled one is veiled — with a hole cut where the
invisible window stands, because the veil's mask took it for an opaque pane in front.

**Whether Outlook fades or orders out is unmeasured** — reproduction on the machine that has it is off
the table. So the second hole is closed too. If it orders out and the destroy notification is missed
(`1790046624`'s premise), the retirement rests on a scan, and a scan's departures are suspended
app-wide whenever the app has *any* on-screen window the join cannot place. An app that keeps one such
window for good — a helper AX never lists, chrome emira declines — pins every departure of that app
forever. Measured in the suite while writing this: the same guard also stops a native tab switch from
succeeding in such an app, so the old tab's id lingers and the new tab arrives as a fresh window.

## Implementation

**`Event.windowShown(id, Bool)` makes "drawn" a fact in the core.** `WindowListEntry` carries
`kCGWindowAlpha`, and `isDrawn` is on screen and above `invisibleAlpha` (0.01 — a fade does not land on
zero; AppKit's last frame measured 0.0008). `WorldWatcher.noteShown` compares against what it last told
the core and reports only changes. `World.unshown` holds it; `isOnScreen` reads it for untiled windows
only — a tiled window's place is the strip's, and the last placement pass already answered it. Every
reader of `isOnScreen` inherits it: the hoist set, `hoistClicked`, `window(at:)` for focus-follows-mouse,
and the departure hand-off in `lastFocusedOnScreen`. Rejected: a shell-side check in `HoistPanels` before
revealing, which would fix the picture and leave focus-follows-mouse and the hand-off pointing at a
window nobody can see — a second opinion about what is on the screen, in the one place `PRINCIPLES`
says there is none.

**It is read twice.** Every reconciliation, which is free — the list is already read. And
`fadeAllowance` (0.4 s) after every focus report, since that is when a float is buried and when an app
hands focus back from the window it is fading: read at the report, the window is still at the top of
its curve, and the next reconciliation is up to 3 s away with a picture of nothing standing meanwhile.
Only the latest report's check runs. It sits behind the paint gate and is rescheduled while a
transition paints. The first cut read the list off the main thread instead; `IMPLEMENTATION` records
that as measured to relocate the wait onto our own frame commit rather than remove it, so it was
withdrawn before landing.

**The veil's mask skips a window drawn at nothing** (`StackedWindow.current`): it shows no pixels, so it
is in front of nothing. Read there directly rather than through the core, since the mask is about
pixels and already reads the server itself.

**The join ignores what the watcher has written off** (`AXEnumerator.Unmanageable`). Suggested in review
as "ignore the ones we'll never bind", and it is strictly narrower than a rectangle test at the same
job: it asks no frame, so a stale recorded frame — which a column mid-move has — cannot let a departure
through. Entries by number: those `unaccounted` has counted for `maxReconcileRounds` rounds. AX windows
by element (`AXWindow` is `Hashable` on `CFEqual`): `Report.rejected` carries them out, and
`rejectedSince` dates each by the reconciliation round it was first refused in, forgetting it the first
time a scan of its app does not repeat it. Both on reconciliation's budget, deliberately not the retry
chain's: the chain gives up after ~0.3 s, which is close enough to a slow app's ⌘T race to cost a tab
group its column. "Written off" is reached *at* the last round rather than after it, so a stray that
appears together with a window that dies unheard is written off on the same round the off-glass
question spends its last scan.

## Observations

- **Validated in the suite, not on the daemon.** The probe reproduction above ran against the daemon
  before the change. After it, another session's daemon held the socket (a worktree's build, with
  tracing), so the end-to-end run — `Reminder.app` in the scratchpad, `alpha`/`alphaResize`/`orderOut`
  modes, with a focus bounce to bury the float — is still owed.
- A float that fades while focus does not move is caught by reconciliation only, up to 3 s later.
- A window caught mid fade-in by a reconciliation read is off the screen to the core until the next
  one — up to 3 s with no hoist and no focus-follows-mouse onto it. Unobserved; the read would have to
  land inside a ~0.25 s window.
- `fadeAllowance` is AppKit's fade with margin. An app with a slower fade is caught by the next
  reconciliation instead.
- The fact is reported for tiled windows too and ignored for them. A tiled window its app stops
  drawing still holds its column.
- Unrelated and pre-existing: `HoistPanels`' header and `IMPLEMENTATION`'s *Hoisting* describe a second
  "burial" film, but `apply` films only when a panel is new or its size changed.
- New tests: `NativeTabIncompleteScanTests` (an entry and a rejection written off, and the race left
  intact for everything else), `LiveWorldTests` (a window that closed unheard beside a stray and beside
  a permanent rejection; the drawn reading reported once and back; the fade check, and its paint gate),
  `HoistTests` (an undrawn float is not hoisted or clickable; a tiled one keeps its place). The five
  tests of the written-off rule, join and watcher, all fail with the guard reverted to its app-wide form.
